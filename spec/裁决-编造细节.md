# 裁决四：legit 与胡编，靠什么分开

**日期**：2026-10-26
**裁决人**：大乔（Lead）
**触发**：kernel-dev 探针实测——三问全套能拒掉三种胡编，但也拒掉了 legit；他建议把 legit 交给 `groundedIn` 单路

---

## 一、探针暴露的真问题

```
legit   （他把一件事拖到没意义了才说）  主路不成立（与材料共享片段为 0）  ← 要过，被拒
domain  （他上个月去爬山）              主路不成立（共享片段只有 他/自己/一个） ← 要拒，被拒 ✓
wrong   （他信不过我）                  主路不成立                          ← 要拒，被拒 ✓
grandiose（他就是这样的人）             第一问就死（is 已删）                ← 要拒，被拒 ✓
```

**legit 和 domain 在「字面」上长得一模一样：都跟材料零共享。**

kernel-dev 的结论是「区分不了，只能靠模型声明」。**方向对，但理由错，而且他漏了一个更危险的地方。**

---

## 二、kernel-dev 方案的危险

如果 `groundedIn` 变成**唯一**能救 legit 的路，那么：

> 所有判断都必须走这条路 → 等于让模型自己说「我这句话有依据」→ 它说了算。

**这比加闸更危险。** 加闸最坏是拦错，这个最坏是**放行一切**——模型随口声明「我依据第 1 条」，内核就信了。而且 `groundedIn` 的硬约束只是「序号必须存在」，不等于「序号真的能支撑这句话」。

---

## 三、裁决：legit 与 domain 的差别不在句式，在「方向」

仔细看这两句：

| | legit | domain |
|---|---|---|
| 说的是什么 | **这个人的做法**（他总这样） | **一件具体的事**（上个月去爬山） |
| 有没有说时间地点 | 没有 | **有**（上个月） |
| 材料里有没有对应 | 有（几件事都指向同一个做法） | 没有（一次都没发生过） |
| 能不能被将来的事推翻 | 能 | 不能（它压根没发生，无从推翻） |

**关键差别不是句式，是：它是不是从「多次材料」里归纳出来的。**

legit 是一个**归纳**：三件事 → 一个做法。
domain 是一个**捏造**：零件事 → 一件具体的事。

---

## 四、改成：`groundedIn` + 「归纳证据」

### `groundedIn` 保留，但**不许它是唯一的路**

三条路全部保留，`groundedIn` 只是第三路。**它的加入不改变前两路的判定。**

### 新增第四问（只对 `groundedIn` 生效）

模型声明 `groundedIn: [1,2,3]` 时，内核必须复核：

1. **序号真实存在**（已有约束）
2. **被指的这几条材料，必须能归纳出这个 `relation`** —— 也就是说：这几条材料的骨架里，**至少两条**含同一 `relation` 的语义信号
3. **判断里不许出现材料里没有的具体时点/地点/数量**（「上个月」「爬山」这类）—— 这叫「编造细节」

只要第 2 或第 3 不成立 → `groundedIn` 作废，退回去走字面 grounding。

### 为什么这样能分开 legit 和 domain

- `legit` 声明 `groundedIn: [1,2,3]` → 三条材料都在说「同一类做法」→ 第 2 成立；正文没有时点地点 → 第 3 成立 → **放行**
- `domain` 如果声明 `groundedIn: [1,2,3]` → 那三条材料里没有爬山这件事 → 第 3 不成立（「上个月」是材料里没有的时点）→ **拦下**
- `domain` 如果不声明 → 走字面 → 零共享 → **拦下**

**两条路都拦得住。** 这不是靠猜句式，是靠「编造的具体细节」和「归纳的抽象说法」的区别。
