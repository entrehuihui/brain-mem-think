# 裁决：主题归一必须换掉词表法

**日期**：2026-10-26
**裁决人**：大乔（Lead）
**依据**：`acceptance/f_unknown_wording.mjs` 实测 + `acceptance/run_all.mjs` 全表 + 两份互相打架的词表

---

## 一、实测证据

### 1. 陌生说法全部落空

```
F1.convergence_rate   5 种说法收敛到同一主题的有 0 种（主题分布：无）  actual=0 min=3
F1b.not_all_loose     不许全部落到 loose（=一个都没认出来）：无
F2.produced_judgment  喂完 10 条后库里的判断条数（0 = 陌生说法全废）  actual=0 min=1
```

同一件事换 5 种说法，**一种都没认出来**，全落 `loose`。

### 2. 词表是两套，且互相不一致

| 位置 | 内容 |
|---|---|
| `src/mind.mjs:33` `THEME_SIGNALS` | `tired: ['累','乏','困','精神']`、`busy`、`sleep: ['睡','熬夜','醒','失明']` … |
| `src/curiosity.mjs:31` `THEME_HINT_WORDS` | 同一批词又抄了一遍，另加 `say: ['说','讲','问','答应','道歉']` |

`mind.mjs:49` 是**首个命中即返回**（`if (...some(...)) return key`），所以一句话里同时出现「说」和「熬夜」时，谁在词表里排在前就算谁。

**实测过的具体错例**：`主人熬夜到后半夜` 被判成 `say`（因为带「说」字），不是 `sleep`。

### 3. 它污染了所有下游判据

主题认错 → 同主题的判断落不到一个槽 → 后面每一条能力全废：

- `b_think_more`：`B0.S3_has_live_judgment actual=0`、`B9.second_topic_also_evolves actual=1`（换主题也不演变）
- `c_curiosity`：`C3B.fires_capped actual=7 max=3`（追问次数失控，因为每次都被当成新主题）
- `d_change_mind`：`D0A.retired_appears retired=0`
- `e_forget_by_new`：`E3.fade_is_traceable because=(空)`、`E7.still_remembers_something 空`
- `selftest.b/c/d/e.good 必须绿，实际=红` ← **元验收已经证明有判据在冤枉好实现**

### 4. 两个成员各自独立指出过

- kernel-dev：「主题归一还是词表法……真模型措辞一变就散架，这是整个内核最脆的一环」
- shell-arch：注入层拿不到稳定主题就没法写「同一件事」

---

## 二、裁决

**主题归一不许再用关键词表。** 两层词表全部删除。

### 改成：骨架 + 谓词驱动

主题键不再由「输入里出现了什么字」决定，改由**判断本身的结构**决定：

```
themeKey = `${relation}|${subject}`
```

- `relation` —— 必须出自 `judge.PREDICATES` 闭集（已有约束，规格 R6 一样的要求）
- `subject` —— 已经是规范化后的短标签，不许是原话片段

### 三条硬要求

1. **主题键只能从「已经熔出来的判断」上取，不能从原始输入上取。**
   一条经历还没熔出判断，它就不属于任何主题——这正是「悬而未决」该有的样子。

2. **输入如何关联到主题，只许用两条路**：
   - 与现役判断的骨架重合（`judge.similarity`）
   - 模型在熔的时候**自己指定**它说的是哪个主题（`synth` 返回里带 `theme`，或复用现役判断的 id）

3. **`loose` 不许再作为兜底大口袋。** 关联不上任何现役主题的经历 → 进 forge 窗口当孤立材料，窗口满了就丢。它不会变成一条「我记住了」的判断。

### 为什么这样能解决问题

- 「主人熬夜到后半夜」和「他又是后半夜才睡」，无论怎么措辞，熔出来的 `relation|subject` 会收敛到同一个。
- 不是靠字面像，是靠**模型的理解**——这正是「会思考」和「存储体」的分界：她按自己的理解归类，而不是按关键词匹配。
- 删掉两层词表，`mind.mjs` 和 `curiosity.mjs` 不再有两份互相打架的真相。

## 三、派活

| 负责 | 内容 |
|---|---|
| kernel-dev | 删两层词表；`themeOf()` 改从判断结构取键；`curiosity` 改成按主题键 + 骨架重合触发；`loose` 不再兜底 |

| 全体 | **接真模型之前不许动主题归一的判据**；这一版是靠结构收敛，不是靠词表命中 |

---

## 四、代价（明说）

- **收敛变慢。** 陌生说法第一次进来不会立刻归到旧主题，要先熔出一条判断，才拿它的 `relation|subject` 去比对。第一次会慢一步，这是对的——她本来就得先想一次，才知道这是同一件事。
- **模型权重变大。** 归类从「内核匹配」变成「模型理解」。模型一弱，主题就散。这是把责任放在该放的位置上。
- **`loose` 不再兜底后，孤立经历会真的丢掉。** 这正是主人要的：不改变她的事，不值得占位置。

---

*一句话：存储体按字面归类，脑子按理解归类。*
