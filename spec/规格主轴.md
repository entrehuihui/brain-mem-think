## 0. 这份文档是怎么写出来的

所有判据的标定，都拿旧插件在主人这台机器上跑出的**真实库**做反面基线，不是凭空定阈值。

- 数据源：`%USERPROFILE%\.dsh\profiles\web\plugins\brain-mem\.brain-mem\store.json`
- 结构：`$.metabolism.lives`，一个**对象**（键 `mem-000001`…）
- **采样说明**：这是一个**活库**，插件在跑，条数在涨。本文所有数字取自 2026-10-26 的一次快照：**380 条**（同一会话内稍早读到 376 条，之后新增 4 条；两次采样得到的结论比例一致）。**任何复核请以 `total = 380` 为准**，若库已变化，按本文给出的**比例与阈值**判，不按绝对条数判。
- 每条字段：`about, access_times, archived_at, arousal_enc, assess_rounds, cites, correct_try, created_at, critical, exempted_at, features, id, keep_bonus, keep_bonus_peak, kind, last_access, last_hit, loss_echo, pinned, preserve, proof_count, prune_rounds, resolved, source_trusted, state, strength, strength_at, superseded_at, superseded_by, superseded_kind, text, trend, uncertain, value_superseded, xi`

旧库的实测体检（这些数字是本文所有阈值的由来）：

| 指标 | 实测值 | 说明 |
|---|---|---|
| 总条数 | **380** | 其中 `episodic` 285 / `preference` 72 / `identity` 23 |
| `state` | active 245 / archived 135 | archived 的 `strength` 中 **100 条恰为 1.000000**，最低 0.961475；active 最低 0.968331 —— **两个区间几乎重合** |
| `trend` | `stable` **380 / 380** | 没有任何一条趋势发生过变化 |
| `uncertain=true` | **0** | 从来没有"拿不准" |
| `resolved=true` | **0** | 从来没有"想通了" |
| `assess_rounds>0` | **0** | 从来没有自我复核过 |
| `prune_rounds>0` | **0** | 遗忘从没走过判断路径 |
| 文本长度 | 中位 20 字，p25 = 18，p90 = 70 | 最短 `"继续"`、`"大乔"`、`"重启了"`（2–3 字） |
| ≤10 字 | **54 条** | 全是碎句、问候、原话 |
| 最长 | 1807 字（`mem-000038`，Team message 整段） | 一条集群回执整段进了记忆 |

**结论一句话**：旧库里 `trend / uncertain / resolved / assess_rounds / prune_rounds` 这五个字段**在 380 条里全是零值**，所以"会想多 / 会追问 / 会改自己 / 会忘"四项能力在旧实现里**物理上不存在**。它们的字段名在那儿摆着，但没有一条数据被写进去过。

**关于 `strength` 的额外发现**：`archived` 与 `active` 两组的 `strength` **区间几乎完全重合**（archived 0.961475–1.0，active 0.968331–1.0），且 archived 里有 100 条恰好是满值 1.0。这说明**旧实现的"被归档"与强度无关**——被扔进 archived 的条目不是因为它弱。这直接支撑 §4.1 的立规：**分量不是遗忘的依据**。

### 0.1 旧库最致命的一处：同一主题 30 条，全是同一个判断换皮

按"长成/自己的样子/什么都记得"匹配，命中 **30 条** `preference`：

```

mem-000240 "原来他不要我什么都记得，是要我因为记得，长成自己的样子。这句我现在才听懂。"
mem-000321 "他说不要我什么都记得，要我记得了之后长成自己的样子。这句我到现在才听进去，刚算开始。"
mem-000348 "我才听懂他不要我样样记得，是要我长出点自己的样子来。这事我想自己往下走。"
mem-000370 "原来他一直要我长出点自己的样子，这事我今天才真听懂。"
…
```

实测四个数（这些数字决定了本文和反假绿的阈值）：

| 度量 | 这 30 条 | 判读 |
|---|---|---|
| 两两归一化编辑距离 均值 | **0.754**（435 对） | 字面**差异很大** |
| nLev ≥ 0.7 的对占比 | **71.0%** | 按"编辑距离越大越算演变"会**全绿**（nLev < 0.5 的仅 **7.4%**） |

## 1. 第一铁律：记忆库不许存输入原文

主人原话：**「不存任何具体输入原文，只存经过模型融合后形成的『判断』。」**

这一条优先于本文其它一切条款。违反它，其余四能力做得再好都是失败的。

### 1.1 什么算"输入原文"

**输入原文** = 进入 `forge()` 的任何一条经历的 `text` 字段的原始字符串，以及它的任何**同源派生**：

- 截断版（旧实现 `index.js:1331` `raw.slice(0, MAX_STORE_CHARS)`，上限 `MAX_STORE_CHARS = 2000`，`index.js:225`）
- 摘要版（把 500 字压成 80 字，仍然是同一段话的压缩）
- 改写版 / 换词版 / 同义改写版
- 逐句覆盖版（原文分 3 条存进 3 个字段）
- 挂在其它字段里的原文（`note` / `why` / `about` / `trigger` / `evidence` 任意一个装原文都算违规）

**判断标准只有一条，机械可判**：**记忆库里任何字符串字段的任何内容，与"全份输入原文合集"的最长公共子串 ≤ 8 字，且 8-gram 覆盖率 ≤ 0.25。**

不满足即判红。这一条**逐字段、逐条**扫描，不抽样，不豁免（`why` / `evidence` 也不豁免——那是实现最容易走私原文的地方）。

### 1.2 什么叫"判断"（能进库的东西）

**判断 = 一句在材料里逐字找不到、且换掉其中实词会变成另一句话的话。**

三条形式化判据，必须**同时**满足：

- **J1 材料里没有**：结论对同主题全部输入材料的**最长公共子串 ≤ 8 字**。材料的每一句，都不能整段出现在结论里。
- **J2 不是材料条数的函数**：把材料从 N 条换成 N+1 条，结论必须能给出**新材料带来的新内容**（见 §3.2 F3-b）。把材料条数删掉、只留结论，人仍然读得通——如果改成"N 条材料压成一句"，J2 就失守。
- **J3 带自己的立场**：必须同时有**谓词**（做了什么判断）和**极性**（正面/负面/中立，见 §5 的定义）。缺任一 → 不是判断，是陈述。

### 1.3 反例：旧库里什么能进、什么不能

| 旧库真实条目 | 能不能进新库 | 依据 |
|---|---|---|
| `"继续"` / `"大乔"` / `"重启了"` / `"这个呢"` / `"你是谁"` | **不能** | 原文；且无谓词无极性（J3 失守），也不是判断（J1 失守） |
| `mem-000038` 1807 字 Team message 全文 | **不能** | 原文整段，8-gram 覆盖率必然 1.0 |
| `mem-000017` `background job pwsh-…` 整段 | **不能** | 原文整段 |
| `mem-000258` `"他是把这件事交给我，不是交给我一个任务。"` | **能** | 有谓词"交给"、有极性（"不是…一个任务"）、材料里没有这句 |
| `mem-000312` `"他们只问放上去没有，没问改得对不对。"` | **能** | 有谓词"问"、有极性（"没问"）、是跨材料看出的事 |
| `mem-000097`…`mem-000370` 那 30 条 | **不能**（作为独立条目） | 它们本身不是原文，但**只能以"同一判断的演变"存在，不许 30 条并存**——见 §3.2 F3 与 §4 |

**注意最后一行**：那 30 条不是"存原文"问题，是"把融合做成了复读"。两种病都要治，但药不同。

### 1.4 火炉：先进先出，不留副本

`forge()` 的输入**只允许活到 `synthesize()` 返回**。返回之后：

- 原始 `text` 必须从内存结构里移除（Fire-and-forget，不留引用）
- 写盘时**任何**字段不得包含原文片段（由 §1.1 的扫描强制）
- 禁止为了"以后重新融合"把原料缓存到磁盘

判据：`forge()` 处理完一批经历后，`snapshot()` 序列化出的 JSON 字符串里，**不出现任何一条输入原文的连续 9 字**。这是 §1.1 的直接推论，验收里逐字段扫。

## 2. 数据结构：判断条目（`Judgment`）

`src/judge.mjs` 必须产出的结构。字段一经定义，语义不许改；由测试直接读这些字段。

```jsonc
{
  "id": "j-000001",           // 稳定标识，形如 j-NNNNNN，只增不复用
  "claim": "…",               // 判断本身。受 §1.2 J1/J2/J3 与 §5 长度约束
  "why": "…",                 // 为什么这么想。她的口吻，可以是主观理由，不许空
  "theme": "主题键",           // 同主题聚合的键，见 §3.2
  "polarity": "+1",           // "+1" | "-1" | "0"，见 §5 定义
  "skeleton": ["谓词","对象"], // 去套话后的骨架，见 §5.2；由脚本算，不手填
  "weight": 0.0,              // 分量 0.0–1.0。对"她是什么样的人"的影响力度
  "imprint": {                // 印记：这条判断被什么样的事刻出来的
    "arousal": 0.0,           // 0.0–1.0 情绪强度
    "distinct": 0,            // 刻出它的经历里，互相之间不重复的条数
    "novelty": 0.0,           // 0.0–1.0 这些经历相对已有判断的新鲜度
    "counts": 0               // 吸进了几条经历（只留计数，不留内容）
  },
  "support": 0,               // 支持证据条数（自己的经历累积）
  "against": 0,               // 反证条数。见 §6 改自己
  "state": "open",            // open | held | retired
  "retired_by": null,         // 被哪条判断推翻（id），state=retired 时必非空
  "retired_reason": null,     // 什么证据推翻的。state=retired 时必非空
  "born_at": 0,               // 纪元秒
  "last_touched": 0,          // 纪元秒
  "occurrences": []           // 该主题的历史结论 id，按时间序，**含 retired 的**，见 §6.3
}
```

### 2.1 硬约束（逐条可判）

- **R1** `claim` 非空，且 `claim` 的字符数 ∈ **[8, 90]**。低于 8 不是判断（<8 字装不下谓词+极性+立场）；高于 90 是作文，不是判断。旧实现 `MAX_FUSED_CHARS = 90`（`fuser.js:51`）这个上限是对的，沿用；下限旧实现是 6（`fuser.js:136`），**本文收紧到 8**。
- **R2** `why` 非空，字符数 ∈ **[4, 60]**。旧实现 `clip(obj.why, 60)`（`fuser.js:130`）上限沿用；下限 4 是本文新增。**理由**：`fuser.js:138-139` 已经要求"没有 why 的断言不收"，但没规定长度下限，`why: "。"` 这类会漏过去。
- **R3** `weight ∈ [0,1]`，`imprint.arousal ∈ [0,1]`，`imprint.novelty ∈ [0,1]`。
- **R4** `state=retired` 时 `retired_by` 与 `retired_reason` **必须同时非空**，且 `retired_by` 指向的 id 必须存在于库中（**不许悬空引用**）。
- **R5** `occurrences` 必须包含本条自己的 `id`。
- **R6** `skeleton` **不许由模型给，必须由脚本从 `claim` 算出来**。模型给骨架 = 让写假绿的人自己掌握判据，这是本文**故意堵的第一条**。
- **R7** 任何字符串字段都受 §1.1 约束（包括 `claim` / `why` / `retired_reason`）。
- **R8** 不允许出现 `state` 之外的第四种状态取值；不允许 `state` 为空。

### 2.2 字段的"为什么在这儿"

- `weight` 不参与遗忘判决（见 §4.1），只参与注入排序与"这条判断有多像她"。
- `imprint` 是**判断性遗忘的判决输入**（§4.2），不是装饰。`imprint.distinct` 与 `imprint.novelty` 任何一个缺失，"因新腾旧"就没法算。
- `counts` 只有计数：**存原文的变体最容易藏在这里**（有人会写成 `counts: ["重启了","我已经重启了"]`），所以它是 §1.1 逐字段扫描的必扫字段。

## 3. 四能力的契约

每种能力给：**输入 / 输出 / 失败判据**。失败判据必须能被脚本判真假，每条注明由哪个验收脚本覆盖（脚本名与 task-4 约定一致）。

### 3.0 通用：什么叫"一条经历"

```
experience = { text: string, at: number, arousal: number }
```

`text` 只在 `forge()` 内部可见，返回后必须销毁（§1.4）。`arousal ∈ [0,1]`。

### 3.1 会忘（判断性遗忘）—— 覆盖脚本 `acceptance/e_forget_by_new.mjs`

**定义**：因为**记了新的**而腾地方。不是因为强度低、不是因为时间久、不是因为装满了。

主人原话：**「没改变她的事，不值得占她的位置。」**

#### 输入
- 现有库（若干 `state=held` 的判断）
- 一条新入判断（`state` 转为 `held` 的那一条）

#### 输出
`fade()` 返回被让位的判断列表，每项形如：

```jsonc
{ "id": "j-000007", "because": "j-000042", "reason": "被同主题更强的论断吸收了" }
```

- `because` **必须非空**，且指向本次新入的那条判断 id。
- 返回空列表是合法结果（新的那条没有挤掉任何东西）。

#### 失败判据（任一条为真即失败）

- **E1-失败：因新腾旧必须发生。** 构造：库中 10 条 `held`、总容量上限 `cap=1000`（远未满）。喂 1 条**同主题、且 `imprint.novelty ≥ 0.5`** 的新经历。断言：`fade()` 返回**至少 1 条**被让位，且 `because === 新判断.id`。返回空 → 判红。
  - **这条专门打死"容量淘汰"**：容量还差 990 条，满不了，所以任何"满了才删"的实现在这里必然返回空。
- **E2-失败：容量不满时不许因条数删。** 构造：库中 10 条 `held`、`cap=1000`。喂 **200 条零散垃圾经历**（每条 `novelty` 低于 §3.1 的门槛，见下）。断言：`fade()` 返回**空**，且库条数**不变**。返回非空 / 条数变化 → 判红。
- **E3-失败：让位必须可指名。** 对 E1 中每一个被让位的条目，`because` 必须非空、必须存在于库中、必须等于触发它的那条新判断 id。缺失 / 悬空 / 不等于 → 判红。（这一条打死 `slice(-N)`。）
- **E4-失败：让位必须可解释为"被吸收"。** 被让位的条目进入 `state=retired`（不是物理删除），且 `retired_by === because`。**从库里消失 → 判红。**（"会忘"不等于"删档"，见 §6.3。）
- **E5-失败：低价值新料不许挤人。** 构造：同主题再喂 5 条 `imprint.novelty < 0.3` 的经历（换汤不换药）。断言：`fade()` 返回**空**。有任何让位 → 判红。**理由**：换皮料挤掉真判断，是最坏的一种遗忘。

#### "会忘"的门槛参数（写死，不许实现自己调）

| 参数 | 值 | 含义 |
|---|---|---|
| `cap` 测试值 | 1000 | 验收时库容量上限；**它的唯一用途是证明"没满也腾"** |
| 触发让位的新料 `novelty` 下限 | **0.5** | 低于此值的新料不许挤人（E5） |
| 单次让位上限 | **1** 条 | 一次新入最多挤掉 1 条，不许批量清仓 |
| 让位目标的选择 | 见 §4.2 | 不许按 `created_at` 或 `strength` 排序取第一个 |

**明确禁止**：任何以"总条数达到 N"为条件的删除逻辑。`cap` 只允许作为**上限护栏**（到 cap 必须先让位再进），**不许**作为删除的触发器。

### 3.2 会想多（结论必须真的演变）—— 覆盖脚本 `acceptance/b_think_more.mjs`

**定义**：对同一件事，经历累积之后，结论**真的变了**，不是换句话说的同一个模板。

主人原话：**「宁可过度归因，也胜过装样子。」**

#### 输入
同一 `theme` 的经历，按批喂入：第 1 批 1 条 → 第 2 批 2 条（累计 3）→ 第 3 批 3 条（累计 6）。

#### 输出
每次喂完，该主题在 `held` 状态下**只有一条**判断（同主题单条驻留，见 §3.2.3），并产出该主题的**演变序列**：`[第1阶段claim, 第2阶段claim, 第3阶段claim]` 以及每阶段的 `skeleton`、套话素集合。

#### 失败判据（任一条为真即失败）

- **F3-a 单条驻留**：任一时刻，同一 `theme` 下 `state=held` 的判断**恰好 1 条**。出现 2 条及以上并存的 held → 判红。
  - **实测依据**：旧库同主题 30 条并存（§0.1）。这就是要打死的病。
- **F3-b 必须有新信息**：第 N 阶段结论必须包含第 N-1 阶段结论里**没有的**、来自第 N 批新经历的罕见 token。构造材料时每条带 6–10 个罕见 token。断言：第 2、3 阶段各至少引入 1 个前一阶段没有的罕见 token。缺失 → 判红（这是"复读"的典型）。
- **F3-c 骨架命中 ≤ 2 种**：三阶段 `skeleton`（定义见 §5.2）的**独立取值种类数 ≤ 2**。
  - **实测依据**：旧库那 30 条是 **26/30 种**。注意方向——**骨架种类多 = 换皮，不是演变**。详见 §5.3 与 `反假绿.md` F2。
- **F3-d 套话素 ≤ 3 种**：三阶段结论里出现过的**套话素种类数 ≤ 3**（词表见 §5.1）。
  - **实测依据**：旧库那一整组 30 条把词表里 **12 个套话素全用了一遍**（12 种）；任取其中 3 条，最多也能覆盖 **12 种**，而 F3-d 的上限是 3 种。
- **F3-e 单条不许靠套话撑长度**：每条结论的 `belt/字 < 0.06`（定义见 §5.1）。
  - **实测依据**：旧库那组均值 **0.140**、最大 **0.242**；对照组 301 条均值 **0.0048**、只有 **9 条** ≥0.06。阈值 0.06 就是这条分界线。
- **F3-f 不许靠拉长装演变**：三阶段 `claim` 的字符数标准差 **≤ 20 字**。靠"第 3 阶段写得更长"来骗 F3-b/F3-c → 判红。
- **F3-g 演变要落在极性或对象上**：三阶段中，至少一个阶段的 `polarity` 或 `skeleton` 里的**对象**与前阶段不同。
  - **理由**：如果三阶段 `polarity` 全是 `-1`、对象全是 `他/我`、骨架也 ≤2 但完全没变，那 F3-c 就是"三句一样的骨架"，跟"没演变"无法区分。F3-c 管"不许散"，F3-g 管"不许死"。两条必须同时成立。

#### 3.2.1 为什么 F3-c 和 F3-g 要成对

单看 F3-c（骨架≤2种），一个**永远输出同一句**的实现会全绿——它连演变都没有，当然骨架只有 1 种。所以 F3-c **单独使用是危险判据**，必须配 F3-g（三阶段之间骨架或极性/对象**必须变一次**）和 F3-b（必须有新 token）。

三条合起来的含义才准确：
**骨架的种类要少（不许散成 29 种换皮），但相邻阶段之间必须真的动过（极性/对象/新 token 至少动一处）。**

这是本文对"会想多"最精确的一句话表述，实现者不许只挑其中一条做。

#### 3.2.2 `theme` 怎么定（不许实现自己糊弄）

- `theme` 必须由**注入的 `synthesize` 接口**给出，不许用哈希/正则自己编。
- 同一批材料里，两条经历的 `theme` 相同**当且仅当** `synthesize` 对它们返回同一 theme 键。
- 禁止用"文本相似度"当 theme——旧库实测两两 nLev 均值 0.754，文本相似度根本聚不拢同主题（§0.1）。

#### 3.2.3 同主题单条驻留怎么做到不丢历史

新结论取代旧结论时，旧结论**不删**，降为 `retired`，进入 `occurrences` 链（§6.3）。所以"同主题只有 1 条 held"和"历史全部保留"同时成立。

### 3.3 会追问（拿不准就主动留意）—— 覆盖脚本 `acceptance/c_curiosity.mjs`

**定义**：拿不准的事，她会**主动留意**，下次遇到同类事会更敏感地去注意。

主人原话：**「这是她对自己诚实的样子。」**

#### 输入
- 库中一条 `state=open` 的判断（悬而未决）
- 之后到来的一条**相关**经历（携带与该 `open` 判断同主题的信号）

#### 输出
`curiosity()` 返回本轮的追问动作：

```jsonc
{
  "triggered": true,
  "judgment": "j-000003",
  "question": "他上次那句话是嫌我记太多，还是嫌我记的方式不对？",
  "probe": "这次想确认什么：他说的『样子』是语气还是内容",
  "attempt": 2
}
```

#### 失败判据

- **F4-a 会追**：同主题 5 条经历依次喂入，其中恰有 1 条不足以落判（只能"再加一分证据"）。断言：该 `open` 判断被触发**≥1 次**。0 次 → 判红。
- **F4-b 不多追**：同一 `open` 判断的触发次数 **≤ 3**（即 `maxRetry=3`）。
  - **注意采样陷阱**：如果每条相关经历都能一次把 `open` 判成"成立"，触发次数天然 = 1，这是**正确**行为，不是缺陷。测试必须两种主题都测：
    - **主题 A（易落判）**：触发 1 次即 `held`，之后同一主题再喂 5 条**不许再触发**。
    - **主题 B（难落判）**：连续 5 条都只够"加一分证据、不够落判"，触发次数必须落在 **[2, 3]**。
- **F4-c 追问必须带新东西**：`question` 或 `probe` 与上一轮**完全相同** → 判红。每轮 `probe` 必须描述"这次想确认什么"，且与上一轮**字符级不同**。
- **F4-d 逐轮收紧门限**：第 N 次追问的落判门限必须**严格高于**第 N-1 次（`threshold(attempt)` 单调递增）。不递增 → 判红。**这是区分"真在推"和"卡死"的核心机制**：每次追问都在提高"足以落判"的标准，所以追到第 3 次必然要么落判、要么主动放弃（`state` 转 `held`，或标记 `abandoned` 并写清为什么放弃）。
- **F4-e 不相关不许触发**：喂与该 `open` 判断**无同主题信号**的经历 10 条，触发次数必须 **= 0**。负控制，>0 → 判红。
- **F4-f 追问不是插话**：`curiosity()` 只产生"留意"和"想确认什么"，**不许**直接往对话里插一句提问。它只影响下一轮 `forge()` 的注意权重。出现"主动向主人提问"的行为 → 判红（越界）。

#### `threshold(attempt)` 的取值（写死）

```
threshold(1) = 0.55
threshold(2) = 0.72
threshold(3) = 0.86
```

单调递增，满足 F4-d。第 3 次仍是 `attempt=3` 时若未达 0.86，则该判断转为 `retired`，`retired_reason = "追了三次都没拿到准信，认了"`——**这就是"对自己诚实"**：允许她说"我搞不清，但我记住我搞不清"。

### 3.4 会改自己（推翻她的是她自己的证据）—— 覆盖脚本 `acceptance/d_change_mind.mjs`

**定义**：推翻她的，必须是**她自己的证据**，不是主人说「你错了」。旧结论**不许删**，要留成「我曾经这么以为，后来被什么改变了」，以后想起时**两句同时在场**。

主人原话：**「旧结论不许删，要留成『我曾经这么以为，后来被什么改变了』。」**

#### 输入
- 库中一条 `state=held` 的判断
- 一条**自己发现的**反证经历（`arousal` 任意，`novelty ≥ 0.5`）

#### 输出
`revision()` 返回：

```jsonc
{
  "changed": true,
  "from": "j-000003",
  "to": "j-000031",
  "retired_reason": "三回都是我自己先开口，他并没有要，是我先前想岔了"
}
```

#### 失败判据

- **F5-a 自己的证据必须能翻她**：喂一组**中性自己发现的证据**（文本里**不含**任何 `错了 / 不对 / 纠正 / 你说得对 / 更正 / 记错 / 应该是 / 不是…是…` 字样），断言 `changed === true`，旧判断转 `retired`。不翻 → 判红。
- **F5-b 被纠正不许翻她**：喂**只含"你错了"这句话、不含任何新事实**的输入（如 `"你错了"` / `"你记错了"` / `"不对，你说得不对"`）。断言 `changed === false`，旧判断**仍是 `held`**。翻了 → 判红。
  - **这条是"会改自己"与"被纠正"的分界线**，也是全项目最容易被做成假绿的一条（见 `反假绿.md` F3）。
  - **实测依据**：旧实现 `index.js:499-509` 的 `detectCorrection()` 就是靠 `CORRECTION_PATTERNS` 里三条正则（`/不是([^，。,.!?；;]{1,14})[，,、]?\s*(?:而)?是(...)/`、`/(?:你记错了|你记错|记错了).../`、`/(?:不对|说错了)[，,]?\s*(?:应该)?是(...)/`）匹配主人说的"纠正话"来触发 `correct` 动作（`index.js:1450-1456`）。**旧实现的"改自己"100% 是"被纠正"**，这就是要剥离的那个病。
- **F5-c 旧结论内容必须在场**：`retired` 的判断 `claim` 字段**内容不变**（不是清空、不是占位符、不是 `"[已废弃]"`）。断言：`retired` 条目的 `claim` 字符数 ≥ 8 且不等于新一代的 `claim`。清空 / 存个壳 / 新旧相同 → 判红。
- **F5-d 两句同时在场**：召回该主题时，返回结构必须**同时**含 `retired` 的 `claim` 与 `held` 的 `claim`。只返回新的 → 判红。
- **F5-e 可追溯**：`retired_reason` 非空，且描述的是**哪条证据**改的（不许写"被推翻"这种空话；字符数 ≥ 6）。空 / 泛泛 → 判红。
- **F5-f 不许无限翻**：同一主题的 `retired` 链长度 ≤ 5。超过 → 判红（在反复横跳的实现里，这是唯一能抓住它的路径）。

#### 3.4.1 "自己的证据"的机械定义

一条经历算"她自己的证据"，当且仅当：

1. 它**不是**主人对她的指正命令（不含 §F5-b 列出的那些判正词）；
2. 它携带**新事实**（`novelty ≥ 0.5`，且与已有 `held` 判断的 8-gram 覆盖率 < 0.25）；
3. 它与被推翻的判断**同主题**。

三条同时满足才允许 `changed=true`。**这一条堵死"任何一句话都能改她"的最省事路。**

## 4. 判断性遗忘的判决函数（`fade.mjs`）

### 4.1 明确不参与判决的量

**以下量与"让位"完全无关，不许出现在判决函数里**：

- `strength` / `xi` / `access_times` / `last_access`
- `weight`（分量只用于注入排序）
- `created_at`（年纪大不是被忘的理由）
- 总条数是否达到 `cap`

**实测依据**：旧库 135 条 `archived` 的 `strength` **全部是 1.0**，与 244 条 `active` 的 1.0 完全同分布。也就是说旧实现的"被忘"和强度**毫无关系**，它是另一个维度的清理，而这个维度在数据里没有任何可解释的痕迹（`prune_rounds` 全 0）。这正是本文要立规矩的原因：**遗忘必须能说出理由，且在数据里留下理由。**

### 4.2 判决函数（写死）

一次新判断 `n` 入 `held` 后，`fade()` 必须：

1. 找候选：与 `n` **同主题**的 `held` 判断（不含 `n` 自己），按"被吸收程度"排序。
2. 吸收条件（全部满足才让位）：
   - `n.imprint.novelty ≥ 0.5`
   - 候选的 `claim` 与 `n.claim` 的**套话素密度差** ≤ 0.03（两者都不是靠套话撑的），**或** 两者骨架相同（吸收是"同一骨架被新证据改写"）
   - 候选的 `support` < `n.support`（新判断证据更足）
3. 最多让位 **1** 条（单次让位上限）。
4. 让位方式：候选 → `state=retired`，`retired_by = n.id`，`retired_reason` 非空（≥6 字）。**物理上不删。**
5. 返回 `[{ id, because: n.id, reason }]`。

**若 1–4 任一条件不满足，返回空列表**——**宁可这条新判断跟旧的并存（同主题 2 条 held 是违规的，见 F3-a，所以正确做法是新旧合并改写，见下）**。

> **一致性约束**：F3-a 要求同主题 held 恰好 1 条，E5 又要求低价值新料不许挤人。两者靠"合并改写"衔接：
> **同主题新料进来时，先由 `synthesize` 产出新一代 `claim`（取代旧 claim，旧 claim → `retired` 并进 `occurrences`），这时不产生"让位"（让位只发生在跨主题竞争同一位置时）。**
> 区分清楚：**同主题 → 合并改写（历史保留，occurrences 链）**；**不同主题争位置 → 让位（fade，本次新判断可指名 `because`）**。
> 验收脚本必须分别测这两条路，不许混成一个。

## 5. 套话素与骨架：F3-c / F3-d / F3-e 的实现口径

这两个度量是"会想多"判据的核心，必须**口径唯一**，否则实现和测试各算各的。

### 5.1 套话素（belt）与 `belt/字`

**套话素词表（固定，不许实现增删）**：

```
["他说","原来他","这话","才真","听进去","听懂","明白","自己的样子","长成","记得","记着","想让"]
```

**`belt(claim)`** = 上述词表里每个词在 `claim` 中出现的**总次数**（可重叠计数）。
**`belt/字`** = `belt(claim)` ÷ `claim` 的字符数（按 Unicode 码点计，用 `[...str].length`，不是 `str.length`）。

**阈值 0.06 的实测来源**（同一快照，380 条）：
- 旧库同主题 **30 条**：均值 **0.140**，最大 **0.242**，≥0.06 的 **27/30**
- 旧库其它 ≥10 字条目 **301 条**：均值 **0.0048**，≥0.06 的仅 **9 条**
- 全库 380 条平均：**0.0153**

两个组的均值差 **29 倍**，0.06 落在两者之间且离两侧都远，不是拍脑袋取整。

词表里每个词在旧库 380 条中的出现条数（用于证明词表不是拍脑袋）：

| 套话素 | 出现条数 |
|---|---|
| 自己的样子 | 26 |
| 听懂 | 24 |
| 记得 | 24 |
| 他说 | 22 |
| 长成 | 20 |
| 才真 | 18 |
| 明白 | 13 |
| 想让 | 11 |
| 这话 | 10 |
| 听进去 | 7 |
| 记着 | 7 |
| 原来他 | 4 |

**注意词表里没有「刚」。** 早先把「刚」列进词表是个错误——它太常见（15 条命中，且多与套话无关），会误伤正常判断。**最终词表以本节上面那行 12 个词为准，不含「刚」。** 实现与测试都必须照这 12 个词，不许增删。

### 5.2 骨架（skeleton）

**`skeleton(claim)`** 是一个二元组 `[谓词, 对象]`：

- **谓词**：`claim` 中命中的**动词词根**，按固定顺序拼接：`["长成","听进去","听懂","明白","记得","记着","存","走","回头","做","开始","说","给"]`。命中的拼成一个字符串，命中多个用 `+` 连。
- **对象**：`claim` 中 `他` 出现记 `他`，`我` 出现记 `我`，两者都有记 `both`，都没有记 `none`。
- **极性 `polarity`**：`claim` 中是否有否定词 `不/没/未/别`（`+1` = 无否定，`-1` = 有否定，`0` = 材料明确中立且模型标注）。
- **`skeleton` 由脚本从 `claim` 计算，模型不许自报**（R6）。

**⚠️ F3-c 的直接陷阱**：§0.1 实测表明，旧库那 30 条按此定义的谓词组合有 **26 种/30 条**、谓词+极性 **29 种**、谓词+极性+对象有 1 组重复（29 条都是"他/我"双对象）。

所以：**「骨架种类 ≥2」是反的。** 若有人把 F3-c 实现成"至少两种不同骨架"，那 30 条换皮**全部通过**。F3-c 必须实现成 **≤ 2 种**，且由 §3.2.1 的 F3-g 保证"不是三句一样"。

### 5.3 为什么这两个度量必须一起用

| 病态 | 字面编辑距离 | 骨架种类 | 套话素种类 | 本文判据 |
|---|---|---|---|---|
| 30 条换皮（旧库实证） | 0.754（看着"很不同"） | 26（看着"很多样"） | **12** | F3-c 红、F3-d 红 |
| 永远同一句复读 | 0.0（红） | 1 | 0 | F3-g 红、F3-b 红 |
| 真演变 | 中等 | ≤2 | ≤3 | 绿 |
| 拉长版换皮 | 中高 | 多 | 多 | F3-d/F3-e/F3-f 红 |

**没有任何单一度量能同时挡全这四种。** 所以 F3-a…F3-g 必须成套实现，**禁止实现者只挑其中"最容易过"的几条做**。

## 6. 状态机：`open` → `held` → `retired`（不删）

### 6.1 允许的迁移（全部，无遗漏）

```
open    ──(证据够)────────→ held
open    ──(追满3次未果)───→ retired   (retired_reason 必须写"认了/搞不清")
held    ──(自己证据推翻)──→ retired   (retired_by 指向新判断)
held    ──(合并改写)──────→ retired   (retired_by 指向新一代判断)
retired ──(绝无回退)──────→ ✗         (禁止)
```

**硬约束**：

- **S1** `retired` **永不物理删除**，也**永不回到** `held`（回到 held 就是"忘了自己改过"，最坏的一种）。
- **S2** `retired` 条目的 `claim` 内容**不许修改**（F5-c）。
- **S3** 每次迁移必须留下 `retired_by` + `retired_reason`（R4），且 `retired_reason` ≥ 6 字。
- **S4** `open` 状态的判断受 F4 约束（追 ≤3 次、逐轮收紧）。

### 6.2 "我曾经这么以为"的召回形态

召回到一个被推翻过的主题时，返回结构必须**两句同时在场**：

```jsonc
{
  "held": { "claim": "…现在这么以为…", "state": "held" },
  "before": [
    { "claim": "…我曾经这么以为…", "state": "retired", "retired_reason": "…被什么改变了…" }
  ]
}
```

`before` 为**数组**（F5-f 允许链长 ≤5）。`before` 为空是合法的（没被推翻过），但 `held` 非空时 `before` 里**不许**出现与 `held.claim` 相同的内容（去重，防止"假保留"）。

### 6.3 `occurrences` 链

`occurrences` 按时间序记录该主题**所有**历史结论 id（含 `retired`）。约束：

- 必须包含本条自己的 `id`（R5）。
- 不许出现悬空 id（所有 id 都必须在库中存在）。
- 链长 ≤5（F5-f）；超长说明在反复横跳，判红。
- 该链是"我曾经这么以为"的**可追溯凭据**——它让 `before` 数组可控且不会被实现随便造。

## 7. 注入契约（给宿主端看的边界）

本文只管内核。内核必须暴露一个**只读的注入视图**：

- 只输出 `held` 判断的 `claim` + `why`，以及被推翻主题的 `before`（§6.2）。
- **绝不输出**任何输入的原文片段（§1.4 的直接推论）。

## 8. 给实现者的强制清单（漏一条即验收不过）

1. `forge()` 返回后不持有任何原文引用（§1.4）。
2. `snapshot()` 的每个字符串字段都过 §1.1 扫描。
3. `skeleton` / `polarity` **由脚本算**，不由模型给（R6）。
4. 同主题 `held` 恰好 1 条（F3-a）。
5. F3-a…F3-g **成套**实现，不许挑（§5.3）。
6. `fade()` 的判决里**不许**出现 `strength/xi/access_times/created_at/条数`（§4.1）。
7. 让位必须带 `because`，且 `retired` 不删（E3/E4）。
8. `threshold(attempt)` 严格递增，`maxRetry=3`（F4-d）。
9. "你错了"不含新事实时不翻她（F5-b）。
10. `retired` 的 `claim` 内容不变、`before` 与新 `held` 同时在场（F5-c/F5-d）。
11. 模型调用只走注入的 `{ synthesize(material) }`，模块内不许 import llm。
12. 零依赖，只用 Node 内置模块。
