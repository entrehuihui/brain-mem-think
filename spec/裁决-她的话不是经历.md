# 裁决七：她的话不是她的经历

**日期**：2026-10-26
**裁决人**：大乔（Lead）
**触发**：shell-arch 核出正反馈环——「她说的话被下一次归档熔当成经历」

---

## 一、这个环长什么样

```
她说了一句
   ↓
那条话落进会话历史
   ↓
归档熔读这个会话时，把它当成「这段时间发生过的事」
   ↓
熔出一条新判断（而且显得有据可依——毕竟「经历过」）
   ↓
心跳读到新判断，觉得压得重
   ↓
再说一句 → 再归档 → 再熔
```

**她越说越确信，因为每一次说话都在给自己造证据。**

这不是回音壁，回音壁还能听出是回声。**这是一个会自我加固的循环**——像一个人反复对自己说同一句话，最后把它当成了事实。

---

## 二、裁决

### 归档熔的材料里，**只收主人说的话**，不收 `assistant/message`

```
digestSession 的材料白名单：
  ✅ user/message（主人说的）
  ❌ assistant/message（她说的）
  ❌ tool/*（工具调用与结果）
  ❌ system 注入的一切
```

### 理由

**她的判断来自「她怎么经历」，她的输出不是经历，是结果。**

一段会话里主人说的话是「发生了什么」，她说的话是「她怎么反应」——**反应不该被当成新的输入**。

### 宿主侧的未查证（如实记录）

宿主的 `assistant/message` 的 `source` 只有 `provider/model`，**没有「这一轮是谁叫起来的」**（`dsh-llm/lib/types/message.d.ts:148-151`）。

所以想精确剔除「我们自己 followup 推出来的那一轮」是**做不干净的**——这才是一刀切（全都不收）的原因，不是懒。

---

## 三、止损阀：账本不动，就不许开口

**连续 N 次唤醒如果判断库没有任何变化，强制降频。**

理由：**账本不动就是在复读。** 一个没有任何新判断产生、却一直在说话的人，不是在思考，是在吵。

```
判据（可断言）：
  判断库冻结场景跑 100 次 wake → speak ≤ 10
  持续注入真演变跑 100 次 wake → speak 明显更高
```

**这条的意义**：证明她开口的理由是「账本动了」，不是「到点了」。

---

## 四、命门的真相：缝不在第四道闸

我原来以为命门是「`agent/pre-step` 整段替换」那道闸。shell-arch 核出来——**缝在第二道闸**：

- `step()` 里 runtime context 也会被 append 成 `user/message`（`dsh-agent-loop/lib/index.js:1069`、`:1073`）
- suppressor 生效时它是空的；**不生效时它会 append 一条「当前会话路径」**
- `claim` 在 waterfall 之前（`:906` 在 `:909` 之前），`refreshContext` 在 `step` 里又跑一次（`:1053`）

> **「她看不见聊天记录」这件事，挂在「第二道闸有没有在第一次 assemble 之前装好」上。**

**所以红队必须测这个先后顺序，而不是只测替换有没有生效。**

## 五、三条机制保证（写死，进 CI）

### 1. 只有一条出口

```
全插件 `followup(` 只许出现一次（grep 可验，进 CI）
```

**理由**：旧插件 60 秒 6 条的根因是**旁路**——两条出口，一条走去重一条不走。

### 2. `followup` 前先看 `agent.status`，`running` 就这轮跳过

**不排队。** 排在队里就是「等她忙完一口气说好几句」。

### 3. 配额与哈希每次决策后立刻落盘，跨重启读回

- 单独文件 `.mind/wake.json`，**不和判断库同文件**
  - 理由：判断库写坏 = 她人格没了；配额写坏 = 少说两句。**失败等级差一个数量级就不该共用文件。**
- 写入用「临时文件 + fsync + rename」，**不许 truncate 原文件**

### 4. 坏状态一律往「不说」倒，但不许变成永远哑

| 坏状态 | 动作 |
|---|---|
| 文件不存在 | 当作刚装好（能说） |
| JSON 坏了 / schema 不对 | **当作「刚说完话」进入冷却**，整份备份成 `.bad-<时间戳>` 再重建 |
| 写入失败 | **这一次就不说**（记不住就别开口） |
| 崩在写盘中间 | 启动时看到 `crashedMidWake` → **强制这轮 silent** |

**反制**：每过 `maxGapMs` 必须至少醒一次，哪怕结果是 silent。**醒 ≠ 说，不烧 token。**
