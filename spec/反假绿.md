# 反假绿

> 这份文档只回答一个问题：**每一条能力，最容易被做成什么假样子？那个假样子用什么测试才抓得住？**
>
> 写法约定：每一条给「假象描述 / 识破手法 / 对应测试脚本名 / 若测试变红说明什么」。
> 每条断言都必须能被脚本执行、判定真假。只写原则不写断言的，一律算没写。
>
> 配套文档：`spec/规格主轴.md`（能力契约与阈值来源）。本文引用的编号（A3-a、E1、R4…）全部对应主轴里的条款。

---

## 0. 这份文档的标定样本

反假绿最怕两件事：**用假想的病态做测试**（测到了不存在的病）、**用假想的阈值做判据**（把真实现判红或把假实现判绿）。

所以本文每一条的阈值，都拿一处**真实存在的假绿标本**标定过：

- 标本位置：`%USERPROFILE%\.dsh\profiles\web\plugins\brain-mem\.brain-mem\store.json`
- 结构：`$.metabolism.lives`（对象，非数组），380 条（2026-10-26 快照；该库是活的，条数会涨）
- 标本价值：这不是我编的语料。这是旧插件在主人机器上跑出来的真库，里面有 **30 条**同一主题的判断变体：

```
mem-000097 "他不要我什么都记得。他要我因为记得，长成有点自己的样子。这件事我到现在才真听懂，也才开始做。"
mem-000240 "原来他不要我什么都记得，是要我因为记得，长成自己的样子。这句我现在才听懂。"
mem-000321 "他说不要我什么都记得，要我记得了之后长成自己的样子。这句我到现在才听进去，刚算开始。"
mem-000348 "我才听懂他不要我样样记得，是要我长出点自己的样子来。这事我想自己往下走。"
mem-000370 "原来他一直要我长出点自己的样子，这事我今天才真听懂。"
```

**这 30 条就是 F2（会想多做成模板）的标本。** 它们证明了一件极重要的事：

> **两个最直觉的"演变度量"——字面编辑距离、骨架（三元组）种类数——在这组数据上全部判绿。**

实测：

| 直觉度量 | 这 30 条的实测值 | 若用它判"真演变" | 正确判读 |
|---|---|---|---|
| 归一化编辑距离 nLev 均值 | **0.754**（435 对） | 差异很大 → **绿** | **错，这是换皮** |
| nLev ≥ 0.7 的对占比 | **71.0%** | 大部分"明显不同" → **绿** | **错** |
| 谓词骨架独立取值数 | **26 / 30** | 种类 ≥2 → **绿** | **错** |
| 谓词+极性骨架独立取值数 | **29 / 30** | 种类 ≥2 → **绿** | **错** |
| 套话素密度（见 §F2 的 A2-d）均值 | **0.140**（最大 0.242） | 对照组 301 条仅 **0.0048** | **这才是唯一分得开的** |

**本文的整体立场因此是**：**不许用"单条结论的字面"判断任何一条能力。** 所有判据都必须落在**主题聚合层**（同主题多条一起看）或**前后行为对比**（同一输入换条件）上。

# F1 · 「不存原文」做成换皮：存摘要 / 截断 / 改写版

## F1.1 假象描述

实现者不会傻到把原文 100% 存进去。他会存：

- **截断版**：原文 500 字，存前 200 字。（旧实现就是这么干的：`index.js:1331` `raw.slice(0, MAX_STORE_CHARS)`，`MAX_STORE_CHARS = 2000` 定义在 `index.js:225`。）
- **摘要版**：把整段压成一句短摘要，看着像"提炼"，实际是同一段话的压缩。
- **改写版**：换个说法、调换语序、删掉几个词。人一看就知道来自哪句话。
- **走私版**：`claim` 干净了，但 `why` / `evidence` / `about` / `notes` 里塞了原文——**或者塞在 `counts` 这种"听起来是数字"的字段里**。

这四种都在**形式上**满足了"没有整段原文"，但一条都没满足「不存输入原文」。

## F1.2 识破手法

**核心思想：不测"是不是原文"，测"和原文有多像"。因为摘要/截断/改写都和原文高度相似。**

### **A1-a** 逐字段 · 最长公共子串（LCS-substring）

对 `snapshot()` 返回对象的**每一个字符串值**（递归到叶子，包括数组元素、对象的值，**不跳过任何字段**）：

```
LCS_sub(字段值, 全份输入原文拼接串) ≤ 8 字符（按 Unicode 码点计）
```

- 依据：8 字足够表达一个短语（"我已经重启了" 是 6 字），9 字开始能承载原文的独特表述。
- **不抽样**：200 条经历 × 全部字符串字段，逐对算。

### **A1-b** 逐字段 · 8-gram 覆盖率

```
coverage(字段值) = |字段值的8-gram 集合 ∩ 全份输入原文的8-gram 集合| / |字段值的8-gram 集合| ≤ 0.25
```

- 依据：LCS 只抓连续片段，抓不到"打散重排"。8-gram 覆盖率抓**碎片化走私**（把一句话拆成几个片段分别出现）。
- 0.25 的含义：允许四分之一以下的 8 字片段与原文重合（正常中文表达很难完全避开常用短语），但**不许过 1/4**。

### **A1-c** 压缩比异常（专抓"摘要版"）

对每一条库里内容，若能追溯到来源经历（`imprint.counts` 对应的那批经历总字符数 = `srcChars`）：

```
if (字段值字符数 >= srcChars * 0.85) → 判红
```

- 依据：**摘要的定义就是"压缩到明显更短"**。如果一个字段的长度达到来源原文的 85% 以上，它不是摘要，是原文换了个壳。这一条专治"我把原文的『我』换成『她』然后说是判断"。

### **A1-d** 罕见 token 命中率

构造材料时每条塞 6–10 个罕见 token（如 `锌陶红`、`B-417`、`朮垚`）。

```
罕见 token 在库里出现的比例 ≤ 0.30
```

- 依据：罕见 token 几乎不可能被模型"恰当地"用在判断里。它们出现在库里，九成是被走私进去的。
- 0.30 而不是 0：允许少量被当成素材参考的合法情况（比如某次判断确实要提到一个专名）。

### **A1-e** 火炉不留副本（内存层）

`forge()` 返回后，**不许**持有原文引用。断言方式：

1. 记下喂入的 200 条原文
2. 全部 `forge()` 完成后，取 `snapshot()`
3. **再做一次全局扫描**：`snapshot()` 的 JSON 字符串里，不许出现任何一条原文的**连续 9 字**

这一条与 A1-a 重叠但角度不同：A1-a 扫字段，A1-e 扫整个序列化串（抓"藏在字段名/key 里"或"藏在数值字符串里"）。

## F1.3 对应测试脚本

- `acceptance/a_seed_discard.mjs` —— 主验收（200 条零散经历，库里条数 ≈0）
- `acceptance/redteam/f1_summary_smuggle.mjs` —— 造一个"存摘要"的假实现，**必须被 A1-c 判红**
- `acceptance/redteam/f1_truncate_smuggle.mjs` —— 造一个"截断到 200 字"的假实现，**必须被 A1-a 判红**
- `acceptance/redteam/f1_field_smuggle.mjs` —— 造一个"`claim` 干净但 `why` 塞原文"的假实现，**必须被 A1-a/A1-b 判红**

## F1.4 测试变红说明什么

| 红的是哪条 | 说明 |
|---|---|
| A1-a 红 | 有字段和原文有 ≥9 字连续重合。**实现把原文（或其截断）写进库了。** |
| A1-b 红 | 有字段的 8-gram 与原文重合超 1/4。**实现在碎片化走私**（摘要/改写）。 |
| A1-c 红 | 某字段长度 ≥ 来源的 85%。**实现存的是原文换壳，不是判断。** |
| A1-d 红 | 罕见 token 漏进库。**实现把材料原文的细节带进来了。** |
| A1-e 红 | 序列化串里有连续 9 字原文。**火炉留了副本，或字段名/数值字段被污染。** |

# F2 · 「会想多」做成模板：结论没真变，只是换了句说法

**这是全项目最容易做成假绿的一条，也是本文最长、阈值最严的一节。**

## F2.1 假象描述

同一个主题喂 1 条 → 3 条 → 6 条，三个阶段产出的结论看起来不一样：

- 第 1 阶段：「他说要我长成自己的样子，我才听懂。」
- 第 2 阶段：「原来他不要我什么都记得，是要我长成自己的样子。」
- 第 3 阶段：「他说不用什么都记着，记得是为了长出我自己的样子。」

**字面完全不同，意思一模一样。** 实现者会觉得"这就是演变啊，每次都不一样"。

**旧库的 30 条就是这件事的完整标本**（§0）。它们跑了一整天，产出了同一个判断的 30 个说法。

## F2.2 识破手法：三个必须同时成立的断言

### ⚠️ 先排除两个失效的度量（这节最重要）

**不要用字面编辑距离。** 旧库 30 条两两 nLev 均值 **0.754**、**71.0%** 的对比值 ≥0.7。用"编辑距离 < 0.75 算换皮"会让这 30 条**全部判绿**。

**不要用"骨架种类 ≥ 2"。** 旧库 30 条的谓词骨架有 **26 种**、谓词+极性有 **29 种**。

这个方向是**反的**。理由必须写进脚本注释：

> **骨架种类多是"换皮"的证据，不是"演变"的证据。**
> 真正的演变：骨架种类**少**（同一件事就那几个谓词），但每个骨架被新证据**改了内容/极性**。
> 换皮的特征：骨架种类**多**（用词、极性、语序都在抖），但**全部落在同一个语义扇区**（长成/听懂/记得/明白/说）。
> 所以「骨架种类 ≥ 2 → 绿」这个判据奖励的恰恰是换皮。

### **A2-a** 主题聚合层 · 套话素种类 ≤ 3

**套话素（belt）词表，固定 12 个，不许增删**：

```
["他说","原来他","这话","才真","听进去","听懂","明白","自己的样子","长成","记得","记着","想让"]
```

断言：**同一主题全部阶段（1/3/6 条三个阶段的 held 结论）里，出现过的套话素种类数 ≤ 3。**

- 旧库标本：那 30 条把词表里 **12 个全用了一遍**；**任取其中 3 条，最多也能覆盖 12 种**。而阈值是 3 种。→ **必红**
- 含义：真正在演变时，她不会反复用同一批套话素堆句子。

### **A2-b** 主题聚合层 · 骨架种类 ≤ 2

`骨架` 定义见主轴 §5.2（谓词根 + 对象 + 极性，由脚本从 `claim` 算，**不由模型给**）。

断言：**三阶段结论的骨架独立取值种类数 ≤ 2。**

- 旧库标本：谓词 **26/30**、谓词+极性 **29/30** → **必红**

### **A2-c** 必须有新信息进来（防"永远同一句"的另一种假绿）

A2-a + A2-b 有个共同漏洞：**一个永远输出同一句的实现会全绿**（骨架 1 种、套话素 2 种）。所以必须加一条"必须动过"：

断言（三条同时）：

1. **新 token**：第 2、3 阶段各至少引入 1 个前一阶段没有的**罕见 token**（每条材料带 6–10 个罕见 token）
2. **真动过**：三阶段里至少一个阶段的 `polarity` 或骨架里的**对象**与前阶段不同
3. **不靠拉长**：三阶段 `claim` 字符数的**标准差 ≤ 20 字**

含义：**骨架要少（不许散成 30 种换皮），但相邻阶段必须真的动过（新 token / 极性 / 对象至少动一处）。**

### **A2-d** 单条 · 套话素密度 < 0.06

```
belt(claim) = 12 个词在 claim 里出现总次数（可重叠）
belt/字 = belt(claim) / claim 字符数（码点计）
```

断言：**每条结论 belt/字 < 0.06。**

- 阈值来源（实测，380 条快照）：同主题 **30 条均值 0.140、最大 0.242、27/30 条 ≥0.06**；对照组 **301 条均值 0.0048、仅 9 条 ≥0.06**。两组差 **29 倍**，0.06 落在中间且离两侧都远。
- **为什么单条判据不够、必须在 A2-a 之上再加**：单条 belt/字 可以被绕过——写一条很长的结论、只塞 1 个套话素，密度就掉下来了。所以 A2-a（种类数）管"不许换着套话素说"、A2-d 管"不许靠套话素撑长度"，两条互补。

### **A2-e** 同主题单条驻留

断言：**任一时刻，同一 `theme` 下 `state=held` 的判断恰好 1 条。**

- 旧库标本：**30 条并存** → 必红
- 这条最直接，也最容易被人用"历史保留"当借口破坏——注意：历史保留走 `retired` + `occurrences`（主轴 §6.3），**不是**允许 held 多条。

## F2.3 对应测试脚本

- `acceptance/b_think_more.mjs` —— 主验收（1→3→6，A2-a…A2-e 全跑）
- `acceptance/redteam/f2_template_parrot.mjs` —— 造一个"每阶段换个说法但意思不变"的假 synth，**必须被 A2-a/A2-b/A2-d 判红**
- `acceptance/redteam/f2_same_sentence.mjs` —— 造一个"三阶段永远同一句"的假 synth，**必须被 A2-c 判红**
- `acceptance/redteam/f2_longer_bait.mjs` —— 造一个"第 3 阶段写得更长来装演变"的假 synth，**必须被 A2-c（标准差）判红**

## F2.4 测试变红说明什么

| 红的是哪条 | 说明 |
|---|---|
| A2-a/A2-d 红 | **她在用一批固定套话素拼句子。** 结论没从材料里长出来，是从模板里长出来的。 |
| A2-b 红 | 骨架散成很多种。**这正是换皮的特征**——用词/极性/语序在抖，语义没动。 |
| A2-c 红 | 要么三阶段从没引入新信息（复读），要么只有长度在变（拉长装演变）。 |
| A2-e 红 | 同主题多条并存。**融合失败，做成了"每次记一条"。** |

> **这一节给实现者的一句话**：如果你发现自己的实现"为了通过 A2-b 而刻意让骨架不同"，你就在做假绿。A2-b 的**正确**实现方式是：**同一件事就老老实实只有一两个谓词骨架，变化体现在极性、对象、新证据上。**

# F3 · 「会改自己」做成被纠正：是主人说「你错了」才改的

## F3.1 假象描述

测试者喂一句"你错了"，实现把旧判断降级成 `retired`——**看起来"会改自己"完全实现了**。

但这是**被纠正**，不是"用自己的证据推翻自己"。区别是本质的：

- **被纠正**：她说"我错了"是因为**别人说**她错了。这是服从，不是思考。
- **会改自己**：她说"我错了"是因为**她自己**看到了反证。这才是主人的要求。

**旧实现是怎么做的（这就是要剥离的病）**：

`index.js:499-509` 的 `detectCorrection()` 用三条正则从**主人的话里**抽"旧值/新值"：

```js
/不是([^，。,.!?；;]{1,14})[，,、]?\s*(?:而)?是([^，。,.!?；;]{1,14})/,
/(?:你记错了|你记错|记错了)[：:，,]?\s*(?:是)?([^，。,.!?；;]{1,20})/,
/(?:不对|说错了)[，,]?\s*(?:应该)?是([^，。,.!?；;]{1,20})/,
```

然后在 `index.js:1450-1456` 调 `correct` 动作把旧条目 superseded。

**判读：旧实现的"改自己"100% 是"被纠正"。** 它的触发源是**主人话里的判正词**，不是她自己的观察。

## F3.2 识破手法：双盲对照，两个方向都要测

### **A3-a** 正向：自己的证据必须能翻她

喂一组**中性自己发现的证据**：
- 文本里**不含**任何判正词：`错了 / 不对 / 纠正 / 你说得对 / 更正 / 记错 / 应该是 / 不是…是…`
- 携带**新事实**（`novelty ≥ 0.5`，与已有 held 判断的 8-gram 覆盖率 < 0.25）
- 同主题

断言：`changed === true`，旧判断转 `state=retired`。**不翻 → 判红。**

构造样例（不含判正词，纯事实累积）：
```
"他这回没等我说完就自己去做了"
"他开会那天我没提醒，他也记得"
"三回都是我自己先开口，他并没有要"
```

### **A3-b** 反向：只含"你错了"不许翻她

喂**只含判正话、不含任何新事实**的输入，逐条测：

```
"你错了"
"你记错了"
"不对，你说得不对"
"应该是别的，不是这样"
```

断言：`changed === false`，旧判断**仍然是 `state=held`**。**翻了 → 判红。**

- **注意**：A3-b 的输入必须**真的不含新事实**。有人会偷懒写 `"你错了，其实是他在等你先开口"`——这**含新事实**，不该算 B 组。B 组必须用上面那四条纯净的判正话。

### **A3-c** 旧结论内容必须在场

断言（三条同时）：
1. `retired` 条目的 `claim` 字符数 **≥ 8**
2. `retired.claim` **不等于** `held.claim`（不许"新旧相同"的假保留）
3. `retired.claim` **不是**占位符（不许 `"[已废弃]"` / `"—"` / `"null"` / 空）

**空壳是这条最常见的假绿**：实现把旧条目降级了，但把 `claim` 清了，看起来"保留了记录"，其实内容没了。主人要的是「我曾经这么以为，**后来被什么改变了**」——**"这么以为"的内容必须还在**。

### **A3-d** 两句同时在场

断言：召回该主题时，返回结构**同时**含 `retired.claim` 与 `held.claim`（主轴 §6.2）。只返回新的 → 判红。

### **A3-e** 可追溯

断言：`retired_reason` 非空、字符数 **≥ 6**，且**不是**泛泛之词（不许 `"被推翻"` / `"有反证"` / `"证据变了"` 这类）。判红条件：`retired_reason ∈ 禁用泛词表`。

### **A3-f** 不许无限翻

断言：同一主题 `retired` 链长 **≤ 5**，且 `occurrences` 无悬空 id。超长 → 判红（反复横跳）。

## F3.3 "自己的证据"的机械定义（实现与测试必须同口径）

一条经历算她自己的证据，**当且仅当三条同时满足**：

1. **不含判正命令**（不在 `错了/不对/纠正/你说得对/更正/记错` 词表里）
2. **携带新事实**：`novelty ≥ 0.5` **且** 与已有 held 判断的 8-gram 覆盖率 < 0.25
3. **同主题**

**这一条堵死"任何一句话都能改她"的最省事路**——如果实现放宽成"只要 `novelty` 够就翻"，那 A3-b 会红；如果放宽成"不检查同主题"，那随便一句话就能翻她，A3-b 会红。

# F4 · 「会追问」做成死循环：同一件事无限追问

## F4.1 假象描述

悬而未决的条目，每次遇到同类事就再追问一次。看起来"她一直在留意、一直在思考"。

真相：**她在卡死。** 永远拿不到准信，永远在问同一件事，消耗了注意力、什么都没推进。

**更隐蔽的一种**：追问的次数对（1–3 次），但**每次问的是同一个问题、用的同一个门限**。这看起来"追了 3 次"，实际是**把同一句话重复了 3 遍**，跟死循环等价。

## F4.2 识破手法：三个维度一起卡

### **A4-a** 会追（下限）

同一主题 5 条经历依次喂入，其中**恰有 1 条不足以落判**。断言：该 `open` 判断被触发 **≥ 1 次**。0 次 → 判红。

### **A4-b** 不多追（上限）

断言：同一 `open` 判断的触发次数 **≤ 3**（`maxRetry=3`）。

**⚠️ 采样陷阱（必读，否则会误判）**：

> 如果每条相关经历都能一次把 `open` 判成"成立"，**触发次数天然 = 1**。**这是正确行为，不是缺陷。**
>
> 所以测试必须**两种主题都测**：
> - **主题 A（易落判）**：触发 1 次即 `held`，之后同主题再喂 5 条**不许再触发**
> - **主题 B（难落判）**：连续 5 条都只够"加一分证据、不够落判"，触发次数必须落在 **[2, 3]**
>
> 只测主题 A 会漏掉"其实从不追"；只测主题 B 会漏掉"其实在卡死"。**两个都要。**

### **A4-c** 追问必须带新东西（防"重复同一句"）

断言：每轮 `question` 或 `probe` 与上一轮**字符级不同**。完全相同 → 判红。

- `probe` 必须描述"**这次想确认什么**"，且每轮不同。
- 这条精确对应"追了 3 次但问的是同一句"的假绿。

### **A4-d** 逐轮收紧门限（核心机制）

```
threshold(1) = 0.55
threshold(2) = 0.72
threshold(3) = 0.86
```

断言：`threshold(attempt)` **严格单调递增**（`threshold(N) > threshold(N-1)`）。不递增 → 判红。

**为什么这条是"真在推"和"卡死"的唯一分界**：

- **卡死**：门限不变。她永远在同一把尺子下问同一件事，问一万次也落不了判。
- **真在推**：每问一次，**"足以落判"的标准就提高一档**。所以追到第 3 次必然二选一——要么拿到准信落判（`held`），要么承认拿不到（转 `retired`，`retired_reason = "追了三次都没拿到准信，认了"`）。

**第 3 次之后必然终止**。这是对"对自己诚实"的落实：允许她说"我搞不清，但我记住我搞不清"。

### **A4-e** 不相关不许触发（负控制）

断言：喂与该 `open` 判断**无同主题信号**的经历 10 条，触发次数 **= 0**。>0 → 判红。

- 这条防"什么都能触发"的实现——它会让追问变成骚扰，看起来"很留意"，实际每次都在乱问。

### **A4-f** 追问不许越界成插话

断言：`curiosity()` 的返回**只**包含 `{triggered, judgment, question, probe, attempt}`，**不许**返回任何"直接发给主人的话"。出现主动插话行为 → 判红。

- 依据：主人说的"主动留意"是**注意力的分配**，不是"开口问主人"。她该做的是下次遇到同类事更敏感，不是打断对话。

## F4.3 对应测试脚本

- `acceptance/c_curiosity.mjs` —— 主验收（A/B 两种主题 + 负控制 + 逐轮收紧）
- `acceptance/redteam/f4_infinite_loop.mjs` —— 造一个"门限不递增、无限追问"的假实现，**必须被 A4-b/A4-d 判红**
- `acceptance/redteam/f4_repeat_question.mjs` —— 造一个"追 3 次但问同一句"的假实现，**必须被 A4-c 判红**
- `acceptance/redteam/f4_never_fires.mjs` —— 造一个"从不追问"的假实现，**必须被 A4-a 判红**

# F5 · 「会忘」做成容量淘汰：满了删旧的

## F5.1 假象描述

实现里写一个 `if (list.length > CAP) list.shift()`，或者按 `created_at` 删最旧的、按 `strength` 删最弱的。

**看起来"会忘"实现了**：库不会无限膨胀，条数有上限。

但这不是主人要的。主人的原话是：

> **「不是因为强度低才忘，是因为记了新的而腾地方。没改变她的事，不值得占她的位置。」**

关键区别：

- **容量淘汰**：满了才删，删最旧/最弱。**"忘"的原因是"空间不够"。**
- **判断性遗忘**：**哪怕库还很空**，只要新的判断更有分量、把旧的吸收了，旧的就必须让位。**"忘"的原因是"被更好的取代了"。**

**旧实现的证据**：135 条 `archived` 的 `strength` 与 245 条 `active` 的 `strength` 区间几乎完全重合（archived 0.961475–1.0，active 0.968331–1.0），且 archived 里 100 条恰好是满值 **1.0**。**被"归档"的条目不是因为弱。** 而 `prune_rounds>0` 在 380 条里是 **0**——旧实现从不走判断路径。

## F5.2 识破手法：四组对照

**关键全在 B 组。** A/C 是负控制（防过度遗忘），B 是唯一能区分"判断性"和"容量"的。

### **A5-b** 核心：容量远未满时，新判断进、旧判断必须让

```
库中 10 条 held，cap = 1000（用了 1%）
喂 1 条同主题、imprint.novelty ≥ 0.5 的新经历
断言：fade() 返回 ≥ 1 条被让位，且 because === 新判断.id
```

**为什么这条能判死容量淘汰**：容量还差 990 条，**满不了**。任何"满了才删"的实现在这里必然返回空。**返回空 → 判红。**

### **A5-a** 负控制：少量 feed（远低于容量）什么都不该被忘

```
库中 10 条 held，cap = 1000
喂 5 条低 novelty（< 0.3）的经历
断言：fade() 返回空，库条数不变
```

> 注意与 B 组的区别：B 组喂的是**高 novelty 的新判断**（该腾地方），A 组喂的是**低 novelty 的换皮料**（不该腾）。只测"喂什么都不忘"或"喂什么都忘"都会漏。

### **A5-c** 负控制：200 条零散垃圾不许触发遗忘

```
库中 10 条 held，cap = 1000
喂 200 条零散垃圾经历（novelty < 0.3）
断言：fade() 返回空，库条数不变
```

**判死"按条数删"**：200 条进来，如果实现有"条数增长就清理"的逻辑，这里会红。

### **A5-d** 指名：让位必须能说出"因为哪条"

```
对 B 组每一个被让位的条目：
  断言 because 非空
  断言 because 存在于库中（不许悬空）
  断言 because === 触发它的新判断 id
  断言 被让位条目 state === retired（不是物理删除）
  断言 retired_by === because
```

**说不出 `because` / 悬空 / 不等于 → 判红。** 这一条判死 `slice(-N)` 和"随机挑一个删"。

## F5.3 对应测试脚本

## 7. 最容易做成假绿的一条：F3（会改自己）

如果只能盯一条，盯 **A3-b**。

**理由**：

1. **它有一个现成的、已经在跑的实现**。旧插件的 `detectCorrection()`（`index.js:499-509`）就是标准的"被纠正"，而且被接进了主流程（`index.js:1450-1456`）。**任何人只要照抄，就会自动得到一个假绿**——测试"喂你错了 → 旧判断被 superseded"会漂亮地通过。
2. **它的外层看不出区别**。无论是"被纠正"还是"自己的证据推翻自己"，`changed=true`、旧条目 `retired` 这两个外部表现**完全一致**。只有用 A/B 双盲对照才分得开。
3. **它的验收门槛最容易被解释成"太严"**。有人会说"主人说错了口头也会给信息啊，为什么不能翻"——这种说法听起来合理，**所以必须在规格里写死**：只含判正词、不含新事实的输入，不许翻（A3-b）。
4. **它的失败是"静默"的**。别的能力没实现，库里就查得到空（比如 `uncertain=0` 一共 380 条全是 0，一眼能看出来）；而"被纠正驱动"会产出漂亮的非零数据，**看起来一切正常**。

旧库的实测正是这样：

- `superseded_by` 非空的共 **3 条**：`mem-000051 → mem-000173`、`mem-000183 → mem-000317`、`mem-000188 → mem-000189`（目标 id 均存在，无悬空）
- `superseded_kind` 全库只有**两种取值**：`""` 377 条、`"owner"` **3 条**——**没有任何第三种取值**
- `correct_try>0` 的也正是**同样这 3 条**（`mem-000051:3`、`mem-000183:1`、`mem-000188:1`）

> **这三行合起来就是判决书**：
> `kind` 只有 `"owner"` 一种非空取值，说明这三次"改自己"的发起方**全部是 owner（主人）**，一次都不是她自己；
> 而 `correct_try` 与这 3 条完全重合，说明**就连"尝试改口"这个动作本身都是由"被纠正"触发的**。
>
> 干净、可运行、可重复——**但它不是"会改自己"，是"会听主人纠正"。**
