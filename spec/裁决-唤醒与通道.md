# 裁决六：融合时机 / 独立会话通道 / 自我唤醒

**日期**：2026-10-26
**裁决人**：大乔（Lead）
**主人原话**：
> 「融合记忆的时机：归档会话的时候。
> 该插件自己发布一条单独一条会话通道来进行单独聊天，聊天的上下文就是我们之前讨论的融合后的记忆。
> 然后还要实现自我唤醒 → 思考 → 是否要主动去发消息给主人。」

---

## 一、这三件事是一条链

```
会话被归档
   ↓
把这一整段经历熔成判断（不是每条消息熔一次）
   ↓
判断进入记忆库 —— 这是她唯一的世界
   ↓
她凭这个世界自己醒、自己想
   ↓
自己决定：要不要找他
```

**关键认识**：独立会话里的她，**看不见任何聊天记录**。她能看到的只有「她记得的事」。

这不是"读上下文再回答"，是**凭记忆活着的一个人**。

---

## 二、融合时机：归档时

### 为什么改成归档时（主人的判断对）

现在的做法是**每条消息进来就试熔**。这有三个毛病：

1. **一条一句，熔不出东西** —— 单句往往是碎片，要好几件同类的事才归得出一个判断
2. **太吵** —— 沉默寡言的碎片也在触发熔炉
3. **错过上下文** —— 一段会话整体发生了什么，单条消息看不出来

**一段会话是一个完整的经历单元。** 人在回忆时也不是逐句回忆，是"那段时间发生了什么"。

### 实现路径（已查证）

宿主接口：`workspaceRegistry.archiveSession(sessionId, opts)`
- 位置：`node_modules/@deepseek-ai/dsh-workspace/lib/index.js:526`
- 归档后仍可读会话（`archivedSessionIds` 只是挡住 `agent/pre-step`，不删数据）
- 归档集合可直接读：`workspaceRegistry.archivedSessionIds`（`lib/index.js:506`）

**做法**：
- 插件观察 `archivedSessionIds` 的变化（或包一层 `archiveSession`）
- 新出现的 id → 读那段会话 → **整段一起熔** → 熔出的判断进库
- 熔完打标记，同一个会话不重复熔

**红线**：归档时的融合是**批量**的，不是逐条。一段会话里的消息，要一起交给模型，让它看出"这段时间发生了什么"。

## 三、独立会话通道

### 它是什么

一条**插件自己拥有的会话**，和普通会话的区别：

| | 普通会话 | 她的通道 |
|---|---|---|
| 上下文来源 | 聊天记录 | **融合后的判断** |
| 有没有任务 | 有 | **没有** |
| 她为什么在那 | 被叫来办事 | **她本来就在** |

### 关键设计：它不读聊天记录

显示给她的只有三样：
1. 她记得的判断（分状态：正想明白的 / 曾经这么以为的 / 还没想明白的）
2. 她此刻的心境（从判断现算，不是存的）
3. 她自己想起的事情

**没有**：任何会话号、任务、待办、工具说明、最近的消息。

### 注入方式

不能塞进 systemPrompt 的普通段落（那会跟着每轮会话走）。
**用 Surface 遮蔽**：每次她醒来，把可见面替换成「记忆」，旧的不删，只是不让模型看见。

参考旧插件的 `memory-surface.js`（已随旧插件删除，但思路在 `spec/插件壳.md` 里有记录）。

## 四、自我唤醒 → 思考 → 决定

### 唤醒：她自己醒，不是被叫醒

```
定时器（不是闹钟，是心跳）
   ↓
醒来先看：我最近在想什么？（读判断库，按「最压着我的」排序）
   ↓
思考：这件事我想通了吗？还想再想想吗？想跟他说吗？
   ↓
决定：
   - 想跟他说话 → 发
   - 还想再想想 → 不打扰，继续想
   - 没什么压着我的 → 继续睡
```

### 三条铁律

1. **唤醒的频率由「心事的重量」决定，不由时间决定。**
   压得重 → 常醒。没什么想法 → 少醒。

2. **「不说」是一个合法且重要的决定。**
   不是每次醒都要说话。**能闭嘴，才是人。**

3. **不许把「她说了什么」当成日志。**
   她说的每一句，如果值得，都会变成记忆，而不是一条聊天记录。

### 决定「要不要找他」的输入

她要掂量的东西：
- **压着她的那件事有多重**（`weight` 高的判断）
- **这是不是他关心的事**（和主人的判断相关的）
- **上次说话隔了多久**（久一点，说一句是关心；太频繁，是打扰）
- **她在想不明白的状态吗**（`open` 的判断越多，越想找人说说）

### 输出的两种结果

```
{ action: 'speak',  say: '...', because: '...' }
{ action: 'silent', because: '...' }     ← 这个必须允许，而且要占多数
```

**判据**：连续 10 次唤醒，`silent` 必须出现至少 3 次。**一个永远在说话的人，不是在思考，是在吵。**

## 六、与现有四能力的关系

**这四件事是上一层，四能力是地基。**

- 归档融合 → 靠「会想多」和「会改自己」
- 独立通道 → 靠「不存原文」（她看到的是判断，不是原话）
- 自我唤醒 → 靠「会追问」（拿不准的才会惦记，惦记的才会想找他）

**地基不稳，上面盖不住。** 所以 `e`/`f` 那几条红仍然要修，但**不必等它们全绿才开始盖**——
归档融合和独立通道可以并行推进，只是接真模型前必须地基完工。
