# 调研：桌宠插件们怎么「自己醒」

**日期**：2026-10-26
**调研人**：大乔（Lead）
**起因**：主人说「自己醒 = 没人在，她自己想起来。这个你可以去借鉴现在很火的大肥鱼桌宠插件，但真正要不要找主人聊天，它的思考要经过 LLM 模型去判断」

---

## 一、查到的（含出处）

| 插件 | 形态 | 怎么醒 | 用 LLM 吗 |
|---|---|---|---|
| **大肥鱼 dsh-dafeiyu**（瓜皮老花生 QCYTTSN） | 桌面层渲染的鲸鱼 | 镜像 agent 真实状态：思考/工作/等确认/完成，进度读自任务列表 | **不画图不用 LLM**，气泡文案是固定语料 |
| **大肥鱼独立版**（1190fasheqi，本机 `D:\dsh\scratch\dafeiyu-src` 是它的插件化版本） | 透明桌宠 | 18 个动作状态机（IDLE/BLINK/THINKING/WALKING…） | 独立版有「AI 对话」，插件版**明确删掉**（`docs__PRODUCT_SCOPE.md`：「不加入第二套 DeepSeek API 对话，不保存 API Key，不维护聊天历史」） |
| **dsh-pet**（seaveyon / b1anker） | 桌面 App + Web 设置面 | 从 `sessions.currentProvideInfo` 读 agent 状态，推导心情 | **README 原文：「零 LLM 调用、零遥测」** |
| **dsh-pet-plugin**（zuoyunlai） | 桌面宠物 | 号称有「proactive speech」、小聊天框「never touches your session」 | 未查证实现细节（raw.githubusercontent 取不到） |

### 关键结论

**市面上没有一个是「自己醒 + 用 LLM 判断要不要说话」的。**

- 大肥鱼的「主动」是**状态触发的固定台词**（`status-copy.js` 里一排 idle 语料轮播）
- dsh-pet 明确写着「零 LLM 调用」
- 所谓「独立聊天框」是**界面独立**（不碰你的会话），不是**思考独立**

**主人要的这件事，得我们自己走。** 这正是它区别于所有现成插件的地方。

## 二、值得借鉴的部分（有出处）

### 1. 状态优先级（来自 Codex Pets，见大肥鱼 `docs__PRODUCT_SCOPE.md`）

> 「需要输入 > 阻塞/失败 > 已完成待查看 > 工作中 > 空闲」

**我们可以借这个思路**：她决定「要不要说话」时，也按优先级——
想不明白的事 > 已想明白但和他有关的 > 日常。

### 2. 「状态要持续循环到下一次真实状态变化，不能播一次就回到 idle」

**这条对我们很关键**：她想的这件事，要一直压着她，直到有真东西改变它。不是想一下就算了。

### 3. 「气泡要能解释『当前状态由哪个任务/事件造成』」（Codex Pets）

**对应我们的 `because`**：她说一句话的时候要能说清「为什么现在说这句」。我们已经有了（`becauseNote`）。

### 4. 「未知事件安全忽略」

**对应我们的降级**：拿不到 llm、拿不到记忆，就当这次没醒，不许报错。

### 5. 「不加入第二套 DeepSeek API 对话，不保存 API Key」（大肥鱼插件版的取舍）

**这条值得警惕**：他们的选择是不做对话。**我们要做的恰恰是相反的事**——因为主人要的不是桌宠，是一个有记忆的人。

## 三、我们的实现路径：心跳 + LLM 判断

### 已有相似实现的地方

旧插件（已删）做过一版：`setInterval` 每分钟醒一次 → 攒「心事」→ 交给模型掂量 → 说/不说。
它的教训（从旧 `trace.log` 里读到的）：
- **冷却永远成立**：因为插件是「每条消息一个进程」，配额存内存里重启就丢 → 必须落盘
- **反复说同一句**：`CLOCK_REPEAT_MS` 定义了但没用上，结果一分钟一条重复
- **「推给她自己那一轮」分支绕过了去重**，导致 6 条 60 秒连发

**这三条全是「落盘」和「去重」没做对。这次必须一开始就做对。**

### 设计要点（已写入 `spec/裁决-唤醒与通道.md`）

```
心跳（不是闹钟）
   ↓
醒来先看：压着我的是哪件？（读判断库，按重量排）
   ↓
交给 LLM：这件事我想通了吗？想跟他说吗？
   ↓
   speak  → 说
   silent → 不说，继续睡
```

**硬判据**：连续 10 次唤醒，`silent` 至少 3 次。
