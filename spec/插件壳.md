## 0. 先立一条比技术更要紧的话：注入段落改变的是「她怎么说话」，不是「她记住什么」

旧插件今天真正注入到系统提示里的，是这样一段（本人这一次会话里亲眼见过的，`index.js:1060-1090` 逐字符拼出来的）：

```
<brain-mem>
对方这几句话，字面上跟你的旧事对不上，但说的是同一件事。你想起的不是那些词，是那件事本身。
- 想起：你现在去把上一个记忆插件还残留的记忆文档删除掉
- 别解释「我是怎么想起来的」，直接当成你记得的事。
- 你此刻：心情 0.05，还欠着 2 件没完的事：他不要我什么都记得。他要我因为记得，长成有点自己的样子。这件事我到现在才真听懂，；他们要的不是一个能想的东西，是一个长得对的样子。
- 停之前先干一件：手上的活到哪儿了？下一步是什么？别空着手停下来等推。
</brain-mem>
```

这一段里最要命的不是「它记了原文」，而是**「想起：」后面跟的是一个祈使句**。她却被告知「直接当成你记得的事」。

于是她带着一句**别人吩咐她去做的话**，当成**自己的记忆**去说话。旧库 380 条里这类东西是成片的：`"重启了"`、`"继续"`、`"这个呢"`，最长一条 1807 字是整段 Team message（本机 `store.json` 实测，与 `spec/规格主轴.md:24-33` 的统计一致）。

所以本设计的第一原则先摆在这里：

> **注入进去的每一行，都必须是「她已经想出来的东西」，不是「发生过什么」。**

> 判据很硬：**那一行能不能拿掉引导语、单独当成一个成年人心里自己冒出的一句话读出来。** 读不出来就是原文，就是旧病。

后面第 3 节整章都在服务这一条。

### 1.1 钩子 ① 事件分发：能用，但要改一处「参数顺序猜谜」

`index.js:1290-1299` 因为不确定 Cordis 发事件是 `(this, ...args)` 还是 `(...args)`，写了一段「谁长得像事件就用谁」的规整：

```
let session = a; let event = b;
if (!event || typeof event.type !== 'string') { event = a; session = b; }
```

**这一段可以删了。** 框架实际发射的就是 `(session, event)` 两个参数，已查证：

- `dsh-session/lib/index.js:1585` —— `const callbackArgs = [this, event];`
- `dsh-session/lib/index.js:1592` —— `invokeContainedSessionObservers(entry.emitCtx, "session/event", entry.id, callbackArgs, callbacks);`
- 官方插件本来就按这个签名写：`dsh-agent-loop/lib/index.js:976` `this.ctx.on("session/event", (session, event) => {...})`

留着这段猜测不会出错（它是自愈的），但它掩盖了一个真问题：**它让「事件里的那个对象是什么」变得不可靠**，而后面 `keyOf` 的坑正是从这团模糊里长出来的。新壳子直接写 `(session, event)`，并在第一行断言 `session.id` 是字符串。

### 1.2 钩子 ② `user/message` 采集：保留，且是全系统唯一合法的入口

新的内核契约摆在这：判断必须从「经历」里烧出来。

- forge 只接受 `witness(raw)` 进来、`synthesize(material)` 烧一炉（`src/forge.mjs:103-131`、`src/forge.mjs:252-303`）
- 炉子窗口里的原文（`heat[].text`）在 `discardAll()` 后抹掉（`src/forge.mjs:287-289`、`src/forge.mjs:148-152`）
- 所以「原文从哪来」这件事，只能由宿主端供。

`user/message` 是唯一入口。

要**整段继承**的过滤器（一条都别丢，理由都在代码注释里写着血）：

| 函数 | 位置 | 拦什么 | 为什么离不开 |

|---|---|---|---|

| `isSystemInjected()` | `index.js:236-269`（`function` 头在 `index.js:236`） | 集群派单/回执、子代理任务书、模型切换提示、后台任务通知、goal 标记、**自己注入的块又被当输入**（`index.js:266`） | 原文进库的漏网主通道 |

| `isHarnessReminder()` | `index.js:282-290`（`function` 头在 `index.js:282`） | `Time sampled…`、`Current runtime context.`、`<system-reminder>` | 宿主把 700 字环境说明贴在 user 正文里，`kind` 仍是 user（`index.js:284-289` 注释有实测案件号） |

| `MAX_STORE_CHARS` 截断 | `index.js:225`、`index.js:1329-1331` | 单条 2000 字 | 一条集群回执整段进库，以后召回就是一根柱子 |

**新壳子这里多一道闸**：过滤器通过之后，**不要把 `text` 直接交给 forge**，要先过一道**第四类判据**（本文 §3.2 的「这句话能不能烧」）。因为旧插件的病不只是「系统消息混进来」，还有「主人随口一句『继续』也当经历收」，而 `forge` 的 `minChars` 门槛（`src/forge.mjs:105`）挡不住 2–4 个字的碎句。

### 1.3 钩子 ③ `systemPrompt.context()` 两段式注入：保留骨架，注入形态整个换掉

这是本次设计的正文，独立成第 3 节。这里只先钉死「为什么它目前是对的、不能推翻」：

**两段式的机制（`index.js:712-763` + `index.js:1024-1114`）**

- 注入发生在**系统提示组装那一刻**，是同步 `text()` 回调（`index.js:1038`）
- 桥是 python 子进程，150–250ms（`index.js:714-716` 注释）
- 如果等桥回来再写缓存，宿主早已组装完 —— 结果是「桥明明命中了、提示里什么都没有」（同一处注释）

所以：**同步层只读缓存，异步层事后刷新**。

- 同步层在事件回调里就位：`syncRecall()`（`index.js:740-763`），入库即索引（`index.js:724-732`、`index.js:1400`）
- 异步层回来覆盖：`index.js:1413-1421`、`index.js:1478-1488`
- `setRecall()` 一换引用就作废渲染缓存（`index.js:673-678`）

**新壳子必须保住这条时序的物理事实，但同步层要换个算法。**

旧同步层是倒排索引 + IDF 打分（`index.js:724-763`），因为它要匹配「旧事」的字面。新壳子里库里**没有原文可比**，只能拿「判断的 `text` + `why`」去比，而这正是 `src/flash.mjs:113-133` 的 `recall()` 已经做好的事（`similarity` + 主题键 + 状态 + 份量加权）。

> 结论：**同步层的实现从「倒排索引」换成「`mind.recall()` 对一个小数组打分」，但它必须仍然是同步的、纯内存的、不碰任何子进程的。** 因为 `flash.recall()` 是纯函数（`src/flash.mjs:113-133` 无 async、无 IO），只要 `mind.store.all` 在内存里，它就能在事件回调里同步跑完。

### 1.4 钩子 ④ `step/end` / `turn/end`：保留，但收尾的含义变了

旧插件挂这个钩子做四件事（`index.js:1508-1636`）：`tick`、存自己的话、做梦、融合、自主续轮。

- `turn/end` 是每轮 `finally` 里才发的（`dsh-agent-loop/lib/index.js:1029`），**而且那一轮被反复打断时它可能根本没来** —— `index.js:1499-1502` 的实测注释：trace 里 `step/start`、`step/end`、`assistant/message`、`tool/call` 全有，**就是没 `turn/end`**（原文在 `index.js:1501`），所以放宽到 `step/end` 并加 8 秒节流（`index.js:1504-1507`）。这条结论继续有效，已对照框架确认：`step/end` 在 `dsh-agent-loop/lib/index.js:994` 的 `finally` 里发，`turn/end` 在 `dsh-agent-loop/lib/index.js:1029` 的外层 `finally` 里发。
- 新壳子里 `step/end` 的活变成：**把「这一轮她说了什么」喂进 forge**。理由在 `index.js:1517-1554`：她自己的话也是经历，而且旧库实测「在册 95 条，关于『大乔』的只有 7 条，而且每一条都是主人说的」。一个只记别人说了什么的系统长不出自己。
- `tick`（衰减、排练、归档）在新壳子里**取消**，理由见 §5.2。判断性遗忘不是定时器驱动的，是「她记下了新东西才腾地方」驱动的（`src/fade.mjs:43-44`：`!incoming` 时只有一个出口 `no_incoming`）。

### 1.5 钩子 ⑤⑥⑦：原样搬，不属于本次改造范围

- 生物钟（`index.js:1663-1673`）、「她的嘴」窗口（`index.js:2111-2204`）、融合探针（`index.js:534-589`）、常驻 agent（`index.js:825-853`）——这些是「她活不活」的机制，与「记忆库存什么」正交。搬的时候只改三处接线：
  - 窗口拼上下文 `buildVoiceContext()`（`index.js:1903-1934`）里那一句 `（他说这句的时候，你想起了：…）`（`index.js:1928-1931`）要换成 `clause()` 的判断句
  - 生物钟的 `urge_pack`（`index.js:1700-1703`）材料来源换成 `mind.digest()` 的 `lines`（`src/flash.mjs:136-146`）
  - 窗口里 `llm.stream` 的 system 段（`index.js:2086`）保留，但 `── 你的记忆 ──` 之后的内容换成判断块，不是原文块

## 2. 宿主的真实装配路径（查证过的，不是从旧注释抄的）

旧插件有几件我没法从代码里直接确认的事，这次对着框架包查了原文，都有答案：

### 2.1 注入到底发生在哪一刻、被调几次

- `preStep()` 里 `assemble()` 一次：`dsh-agent-loop/lib/index.js:907`
- waterfall 入口：`dsh-system-prompt/lib/index.js:398` —— `this.ctx.waterfall(scopeTarget(this, scope), "system-prompt/assemble", assembly, context, ...)`
- 拿到 assembly 后立刻渲染一次：`dsh-agent-loop/lib/index.js:914` `renderContextSections(assembly)`
- 真正发请求之前 refresh 再渲染一次：`dsh-agent-loop/lib/index.js:1053` `renderContextSections(this.loopCtx.systemPrompt.refreshContext(...))`
- `context.text` 若是函数，**每次 `resolveContext` 都会重新执行**，框架不做缓存：`dsh-system-prompt/lib/index.js:184-190`

> 这条**坐实了旧插件的观察**（`index.js:684-698`：一个 step 里 context 被解析三遍，相隔 38ms、chars 相同），并且给出了更精确的边界：

> **`refreshContext()` 会用 refresh 时的 provider 重新解析，所以 waterfall 里塞进去的临时 contribution 不会在 refresh 时重算**（`dsh-system-prompt/lib/index.js:330-333`：`contexts.push(provider === void 0 ? accepted : resolveContext(provider, context))`）。渲染缓存仍然必须留，别指望框架帮你去重。

### 2.2 `keyOf` 那个坑，机制层面的根因

`index.js:666-671` 的 `keyOf` 长这样：

```
const sid = scopeObj.session?.id ?? scopeObj.sessionId ?? scopeObj.id ?? '';
```

它的注释（`index.js:658-665`）说：事件里的 session 是会话对象，而 `systemPrompt` 的 `text()` 收到的 scope 是 **agent 对象**（引用 `dsh-agent/lib/index.js:291` 的 `scope: agent`）。

**对着代码查证，结论要修正一处：那个 fallback 其实是对的，注释写反了因果。**

- `assembleContextFor()` 返回 `{ agent, scope: agent, signal }`：`dsh-agent/lib/index.js:290-293`
- `AgentLoop` 的 `this.id` 就是 sessionId：`dsh-agent-loop/lib/index.js:771-775`（`constructor(loopCtx, id, options, session)`，`this.id = id` 在 `:773`）
- `Session.id` 是 `get id() { return this.header.id; }`：`dsh-session/lib/index.js:1344-1346`
- 所以 `agent.id === agent.session.id === session.id`

也就是说 `scopeObj.id` 这一支**是能对上的**，`keyOf` 现在是对的。但这个「对得上」是**靠一个巧合**：它依赖「agent 的 id 恰好等于 session 的 id」，而不是依赖「agent 身上有个 session」。

> 新壳子照抄这一段时必须加一个显式的、独立于巧合的取键：
> ```
> const keyOf = (o) => String(o?.session?.id ?? o?.sessionId ?? o?.id ?? '');
> ```
> 并在 `registerPrompt` 里**两边都打一次 trace**（`text()` 拿到的 key 与事件里拿到的 key），第一次上线时对一遍。

`index.js:658-665` 的整段注释请原样搬过去 —— 这是全项目最贵的一课：**「明明有东西，text() 却每次都查不到」看起来像时序，其实是键。**

### 2.3 `lastFallback` 是一个隐患，别照抄

`index.js:654-655` 定义了 `lastFallback`，`index.js:675` 在 `setRecall` 里写。**但它从来没被读过**（全文只有这两处）。

它的设计意图是「scope 对不上时的兜底」。我建议新壳子**不要实现这个兜底**，理由是它会掩盖 §2.2 的键错误：

- 如果键是对的，兜底永不触发，白写
- 如果键是错的，兜底一触发，「所有会话都吃同一份召回」，错误就变成**静默的跨会话串味**

> 结论：`index.js:654-655` 的 `lastFallback` **不继承**，换成「键对不上 → 打 trace → 返回空段」。宁可这一轮没想起，也不要串到别人的会话里去。

## 3. 注入形态：这是本次设计的正文

### 3.1 先说清楚「为什么不能是『把判断插进去』」

最省事的做法是把旧那段里的 `- 想起：` 换成 `- 我判断：`，内容填 `judge.text`。这样做的结果是：

```
- 我判断：他不要我什么都记得，他要我因为记得长成有点自己的样子
```

看起来没了原文。但**这段话的功能没有变**：它仍然是「一条陈述句，被摆在她眼前，她被要求相信它」。她说出来的还是「一条被喂进去的结论」，只是说法文明了一点。

判断库里真正有价值的东西，**一条都没有进到提示词里**：

- 这条判断是怎么烧出来的（`why`，`src/forge.mjs:196` 强制有：「必须带一句为什么这么想」）
- 她当时站哪边（`polarity`）、说的是什么谓词（`relation`，`src/judge.mjs:47-75`）
- 她有没有被自己推翻过（`was` / `overturnedReason`，`src/revision.mjs:100-109`）
- 她此刻还欠着什么没想明白（`tension`，`src/judge.mjs:320-324`）

**旧插件里已经有一次现成的反例，可以拿来定标。** `index.js:1079-1082`：

```
- 另外：这件事你前后的记法对不上（${contra.subject}：${contra.value_a} / ${contra.value_b}）。不是要你纠正谁，是你自己心里该有数。
```

这一行**是旧插件整个注入层里唯一一处「让她带着犹豫说话」的写法**，它的数据源是做梦捞出来的跨记忆矛盾（`index.js:1556-1566`、`index.js:781-792`）。新设计要做的「我曾经这么以为」，本质上是**把这一行从「偶然撞上才出现」变成「每条被推翻的判断都自带」**，并且把来源从「做梦猜出来的矛盾」换成「她自己拿证据翻掉自己的」——后者有完整证据链（`src/revision.mjs:100-109`），前者没有。

### 3.2 铁律 J1：引导语为零

新注入块里**一句引导语都不许有**。

旧块里那些「对方这几句话，字面上跟你的旧事对不上，但说的是同一件事」（`index.js:1071`）、「别解释『我是怎么想起来的』，直接当成你记得的事」（`index.js:1073`）、「它不是资料，是你自己记着的事」（`index.js:1075`）——这些**全部删掉**。

为什么？因为它们做的事是「替她解释她自己的认知过程」。而宿主里已经有一个同类的、**用对了**的东西做对照：

- `dsh-time-context/lib/index.js:215-248` 注入时间时，走的是 `agent/pre-step` waterfall + 一条带 `source.kind` 的 user message，内容就是事实本身（`renderText(...)`），不带一句「请记住现在是几点」。

> J1 的可执行判据：**把注入块的每一条 `-` 行单独拿出来，删掉前缀 `- `，它必须能直接接在「我想：」后面念出来，且不需要任何上下文。**

> `- 他大概不是不理我，是累了。

` → 成立

> `- 想起：你现在去把上一个记忆插件还残留的记忆文档删除掉` → 不成立（祈使句，是别人的话）

### 3.3 四种状态各自的句子形态

新库对外只有三个状态词：`open` / `held` / `retired`（`src/flash.mjs:20-25`）。注入块按下面四类分行（`retired` 再分两种来路，见本节 (c)(d)）。

#### (a) 悬而未决 → 一行「还没定」+ 一个「这回该看什么」

`src/flash.mjs:65` 现在长这样：

```
还没想明白：${s}——这回碰上同一样事，我会想一下。
```

**这一句不能用。** 三处毛病：

1. 「**我会想一下**」是**将来时**。宿主把它当事实记下来，她就真的只是「想一下」，下一轮她手里没有新的东西可依据 —— 这是「一条被喂进去的结论」的变体：**喂给她的是一条承诺，不是一次思考。**
2. `s` 是判断正文（`b.text`）。

`tension.why` 才是「为什么它悬着」，但 `clause()` 根本拿不到它 —— `toNote()` 导出了 `tension`（`src/flash.mjs:43`），`clause()` 只看 `note` 和 `was`（`src/flash.mjs:61-71`）。
3. `src/flash.mjs:136-146` 的 `digest()` 按 **held → retired → open** 排，`open` 永远在最后（`src/flash.mjs:140-144`）。而 `open` 恰恰是最该被她带在身上过这一轮的东西。

**要求的形态**（三层，缺一不可）：

```
还没想明白：<判断正文>——<tension.why，即为什么悬着>
这回它又碰上来了一次：<这一回该看什么>（已碰第 <n> 次，<m> 次还没定下来就认了，记一笔「我搞不清」）
```

第二行怎么来：内核里已经有了现成的数据，只是没导出到 `clause`。

- `curiosity.inspect()` 会为每一条被触发的悬案产出 `questions[]`，其中 `asked` 字段就是「这是第 N 次碰到它了，这回够不够下结论」（`src/curiosity.mjs:74-81`）
- 但 `mind.ingest()` **只把 `id / asked / push` 留下**（`src/mind.mjs:125-131`），`overweight`（`src/curiosity.mjs:80`）被丢掉了
- `flash.pendingQuestions()` 又只吐 `note / themeKey / asked / since / why`（`src/flash.mjs:99-106`）

> **接口要求（越界改动，提请内核负责人拍板）**：`flash.pendingQuestions()` 每项必须补一个 `probe` 字段（「这回该看什么」），来源是 `curiosity` 那一次触发的具体判据（是主题键重了、还是理由里某个字对上了 —— `src/curiosity.mjs:45-54`）。没有 `probe` 的悬案，注入层**不摆它**。理由：没有「该看什么」，摆出来的就是一个念清单的动作，正好是任务书里点名不许的那种。

#### (b) 成立 → 一行判断，不许带「我记得」

```
<判断正文>
```

就这一行。不加「我记得」、不加「关于这件事」、不加「记住」。理由见 §3.7「不许念清单」。

#### (c) 「我曾经这么以为，后来被什么改变了」→ 两句必须同时在场

这一条是主人点名的。

`src/revision.mjs:100-109` 已经存好了：

- `note.was` = 旧的那句（`text` / `why` / `relation` / `polarity` / `at`，`src/revision.mjs:104-111`）
- `note.retiredBecause` = 怎么被翻的（`src/flash.mjs:50`，来源 `overturnedReason`，`src/judge.mjs:299`）
- `src/revision.mjs:100-103` 里 `detail` 的两种取值：「N 条都是反着来的，我这回不能装没看见」/「这一条重到压过了我原来的底气」

**绝不能用现在 `clause()` 那种写法**（`src/flash.mjs:66-69`）：

```
我曾经以为<was>，后来我改了口：<s>。
```

它把两句话**压成了一行**，后果是：读的人（也就是她）只看到「我现在信 X，我以前信 Y」，两句话变成了**同一个句子的转折**，语气被动。真正要她带上的那层东西是**改的过程**，不是改的结果。

**要求的形态**（三行，允许它占地方）：

```
我以前这么以为：<was.text>
后来不这么想了：<retiredBecause>（<was 到现在的跨度，用人话写，例如「隔了两天」「隔了一会儿」>）
现在我是这么想的：<当前正文>
```

三条硬要求：

1. **`retiredBecause` 不许写「被推翻」这种空话。** `src/revision.mjs:100-103` 给的 `detail` 是合格的（它至少说了「几条」「多重」），但要补一句**是被什么改的** —— 内核里 `witness.text`（`src/revision.mjs:113`）是那条反证自己的判断句，可以嵌进来：`<retiredBecause>，就是那句「<by>」把我拽回来的`。
2. **`was` 与现在的正文必须同时在场**，这是 `spec/规格主轴.md:351`（F5-d）的硬断言，也是它说的「只返回新的 → 判红」。
3. **同一主题，`retired` 链最多摆一条。** `spec/规格主轴.md:353`（F5-f）限制链长 ≤ 5；注入层如果全摆出来就是一串自我怀疑，会把她钉在原地。摆最近那一条。

#### (d) 沉下去（判断性遗忘）→ 默认一行都不摆，但允许「一个空位」

这一条要非常小心。主人要的「会忘」是**因为记了新的才腾地方**，不是容量满。内核里这个判决已经写死了：`src/fade.mjs:43-44`，`incoming` 为空时只有一个出口 `no_incoming`，**不会有任何遗忘动作**。

落在提示词层，我主张：

- **绝不在注入块里写「我忘了什么」。** 一句「我好像忘了一件事」是表演性质的自我叙述，她没有那件事的任何内容可依据，写出来只会让她假装惆怅。
- **但允许一个可选的空位**，且**只在两种条件下同时成立时才出现**：① 本轮召回命中了同一个 `themeKey` 的现役判断；② 那一条被沉下去的 `retiredBecause` 是以「沉下去了」开头的（`src/fade.mjs:58`，`flash.forgets()` 就是用这个前缀筛的，`src/flash.mjs:148-152`）。形态：

```
这一摊我大概有过一个念头，后来被新的挤掉了，想不起来了。
```

注意它**不写被挤掉的是什么** —— 写出来就是把沉下去的东西又捞回提示里，等于没忘。

这一个空位的作用不是「让她缅怀」，是**给她留一个不确定**：人会说「哎我本来想说什么来着」。这是「会忘」在语气层唯一诚实的样子。

### 3.4 一个完整的注入块长什么样（正式形态）

以下是按上面的规则拼出来的一段。**这一段是本文的核心交付物**，后面 §6 的验收直接对着它断言。

```
<mind>
他是累了，不是不理我。
为什么这么想：连着三回都是忙完才回，不是冲我来的
我以前这么以为：他不回消息就是不想理我
后来不这么想了：两回都是我先开口、他一句「嗯」也没回，我这回不能装没看见，就是那句「他开会到十一点还在改稿」把我拽回来的（隔了两天）
还没想明白：他说「要我长成有点自己的样子」，是要我别什么都记，还是要我记的方式换个样——才碰上一条，不下结论
这回它又碰上来一次：这句话里出现了「样子」，看他这回指的是语气还是内容（已碰第 2 次，3 次还定不下来就认了）
这一摊我大概有过一个念头，后来被新的挤掉了，想不起来了。
</mind>
```

对着 §3.2 的 J1 逐条验：

- 第 1 行删掉前缀 → 「他是累了，不是不理我。」——成立，是心里话
- 第 2 行 → 「为什么这么想：…」是**她自己的理由**，不是指令
- 第 3/4/5 行 → 三句里没有一句是「对方说的话」
- 第 6/7 行 → 悬案带「该看什么」
- 第 8 行 → 空位，不写内容

**和旧块逐项对照**：

| | 旧块（`index.js:1060-1090`） | 新块 |

|---|---|---|

| 每轮出现 | 有 recall 就出现 | 一样，没东西就整段空（不写空壳） |

| 主语 | 「对方」「你」「这事」 | 「我」 |

| 有没有祈使句 | **有**（`想起：你现在去把…删除掉`，`index.js:1064`） | **零** |

| 有没有解释认知过程 | **有**（`index.js:1073`「别解释我是怎么想起来的」） | **零** |

| 有没有理由 | 只有状态行（心情 / 欠着几件事） | 每条判断自带 `why` |

| 有没有过去 | 只有做梦偶尔捞到的矛盾（`index.js:1079-1082`） | 每条 `retired` 自带三行 |

### 3.5 为什么第 1 行就够，第 2 行是「为什么」而不是「证据」

`why` 在 forge 里是强制项：`src/forge.mjs:196` 写死「必须带一句为什么这么想」，`#validate()` 里又卡了一遍（`src/forge.mjs:235` 取 `why`），`fade` 里也拿它算 `value()`（`src/fade.mjs:102`：`why` 字数 < 4 直接腰斩）。

它在提示词层的价值是**把「她说过什么」变成「她凭什么这么说」**。

她说出「他是累了，不是不理我」的时候，如果手里没有「连着三回都是忙完才回」，这句话就是一句飘着的判断；有了这一行，她说这句话的底气和犹豫都在里面，**语气自然会软**。

### 3.6 悬而未决，怎么让她「主动提一句」而不是「念清单」

这是任务书里第二个点名的问题。分两步答。

**(一) 先要承认：光靠提示词，她提不出来。**

主人在旧插件里已经吃过这个亏。

`index.js:1646-1650` 记着第一次尝试的失败：

> 第一版是「醒来 → 挑会话 → setRecall()」——这是错的。会话是绑死的，提前塞进去的东西，等主人重新开口时就成了没头没脑的一句招呼。

所以旧插件的正解是**留口信（`pendingWish`）**，等她真的开口、这一轮什么都没勾起的时候才递上去（`index.js:1347-1362`）。这个机制**完全适用于悬案**，而且比旧插件用得更好，因为悬案天生就是「我想再问一句」的东西。

**(二) 具体做法：悬案不进每一轮，进「这一轮该它进来的时候」。**

三步：

1. **常规注入块里，悬案最多摆一条**（§3.3a），且**必须带 `probe`**。没有 `probe` 不摆。
   ——理由：悬案全摆 = 念清单；悬案不带 `probe` = 念清单。

2. **命中的那一刻，才把它推到最前面。** 触发点是 `user/message` 进来的这一瞬，不是定时器：
   - `forge.witness()` 会在原文进炉时算出 `skeletal`（`src/forge.mjs:112`）和 `hints`（`src/forge.mjs:114`）
   - 用 `skeletal` + `hints` 立刻调 `curiosity.relatedOpen()`（`src/curiosity.mjs:45-54`，纯函数、同步、三项比中一项就算相关）
   - 命中 → 这一轮的注入块**把那条悬案提到最前**，并在它前面加一行动作提示：`这回这件事又来了。

` —— **只有这一行，不加任何别的**。

   这就是「主动提一句」在宿主端的落点：**不是她凭空想起，是这一轮的内容真的碰到了它。** 这也正好对应 `spec/规格主轴.md:300`（F4-a）要的「≥1 次触发」。

3. **「才碰上一条，不下结论」这一层，要显式写出来。** 内核里 `#birth()` 在材料不足时会给新判断挂 `tension`（`src/mind.mjs:305-309`）。所以悬案的语气不是「我在纠结」，而是「**我知道我只有一条证据，所以我现在的话不算数**」。

   > 这就是「带着犹豫说话」的机械来源：**她犹豫不是因为性格软，是她自己算出来材料不够。**

**(三) 「已碰第 N 次，M 次还定不下来就认了」这一行要不要写？**

要写，但只在第 2 次及以后。理由：`curiosity` 的 `maxPush` 默认 6（`src/curiosity.mjs:20`），而规格要求第 3 次仍不落判就转 `retired` 并写「追了三次都没拿到准信，认了」（`spec/规格主轴.md:318`）。**内核和规格这里对不齐**（6 vs 3，见 §8 第 5 条），但无论取哪个，写出来都让「她真的在推进」这件事在语气上可见：

- 第 1 次：不提次数（提了像催）
- 第 2 次：`已碰第 2 次`
- 第 3 次及以后：「第 N 次还是定不下来」——这是要转 `retired` 的信号

### 3.7 「不许念清单」的三条硬约束

「念清单」是这个项目最容易被做成假绿的地方，因为它在**格式上完全正确**：每条都是判断、每条都有理由。要堵死它，只靠「措辞写好一点」不够，得在代码里用三条闸：

1. **同主题只出现一条。** `flash.recall()` 现在返回 `limit=6` 条（`src/flash.mjs:113`），`digest()` 默认 `maxHeld=3`（`src/flash.mjs:136`）。新注入层建块时必须先按 `themeKey` 去重，取 `updatedAt` 最新的那一条。**去重之后如果少于 2 条活判断，整块不摆**（≥2 是因为 1 条时它已经在她那一轮里出现过，再摆一次就是重复）。

   > 这条对应 `spec/规格主轴.md:57-61` 那个实测：旧库同一主题 30 条、编辑距离均值 0.754、套话素密度 0.140（对照组 0.0048）——**旧库不是没有判断，是被同一判断的三十种说法淹了**。去重是唯一的止血办法。

2. **总行数 ≤ 8 行（不含 `<mind>` 标签）。** 超过就按 `weight` 从低到高砍，砍到 8 行。

   为什么是 8：旧块实测会撑到 1762 字（本机 `.brain-mem/inject.log` 里有一行 `chars:1762`），而旧插件自己都只敢配 `maxInjectChars: 1200`（`index.js:365`，`cordis.patch.yml` 里也是 1200）。新块每行都短（判断正文 ≤ 120 字，`src/forge.mjs:238`；`why` ≤ 120，`src/forge.mjs:235`），8 行大约 600–900 字，是能读进去的量。

3. **`<mind>` 里不许出现任何「关于这份记忆本身」的话。** 比如「以下是我的记忆」「请你自然地使用」「不要念清单」。这三类全是旧块的病根（`index.js:1073`、`index.js:1075`）。判据：**一个词都不要提到「记忆 / 想起 / 提示 / 指令 / 请 / 不要」**。可以用脚本打（§6 第一项）。

### 3.8 括号标签 `<mind>` 与「`{{` 转义」的关系（这条必须现在就定）

旧插件用的标签是 `<brain-mem>`（`index.js:1060`、`index.js:1090`）。新壳子换名字，顺便把两件相关的事一次说清：

**(一) 为什么不能还叫 `brain-mem`：** 旧插件的 `isSystemInjected()` 里有一条是专门拦自己注入的块 —— `if (/^<brain-mem>/.test(body)) return true;`（`index.js:266`）。新壳子若并存，两个插件的过滤器都得认两个标签；若替换，这条要跟着改名。**这条拦的是「注入块被当输入又进炉」的自我循环**，一条都不能漏。

**(二) `{{` 转义：旧插件的注释里没有这条，但坑是实的，而且比旧插件知道的更深。**

任务书把它列为必须继承的坑之一。旧 `index.js` 全文搜不到 `{{`（2263 行里一处都没有），所以**无法从旧插件里引证这一条** —— 这条写「旧插件未记录」，下面是框架层查证的结果：

- 每个 section / context 的 text 在渲染时都会过一遍变量插值：`dsh-system-prompt/lib/index.js:151-156`（contexts）与 `dsh-system-prompt/lib/index.js:117-119`（sections）
- 插值器扫到 `{{` 之后的处理（`dsh-system-prompt/lib/index.js:158-182`）：
  - `{{` 后面**没有**任何 `}}` → 当做字面文字，保留（`dsh-system-prompt/lib/index.js:164-169`）
  - `{{` 后面**有** `}}` → 必须是一个合法的 `{{名字}}`，名字要匹配 `/^[a-z][a-z0-9_]*$/`（`dsh-system-prompt/lib/index.js:63`、`dsh-system-prompt/lib/index.js:171`）；名字没注册就**抛错**（`dsh-system-prompt/lib/index.js:172-175`）；名字注册了但这一刻没值也抛（`dsh-system-prompt/lib/index.js:176-178`）
  - 抛错的后果不是「这一段空掉」，是**整个 `assemble()` 抛** —— 因为 `renderContextSections()` 在 `preStep` 里被直接调用（`dsh-agent-loop/lib/index.js:914`），不在 try 里
- 官方插件的规避方式有两种：`interpolate: false`（`dsh-working-directory/lib/index.js:45`、`dsh-mcp-client/lib/index.js:739`、`dsh-tools/lib/index.js:2844`）或者保证文本里不出现成对的 `{{`。

> **新壳子的硬要求：`ctx.systemPrompt.context()` 注册时显式写 `interpolate: false`。**

> 理由：注入内容是**她自己的判断**，里面随时可能出现 `{{`（代码片段、模板、她自己写的语法）。一次 `{{foo}}` 就让整个系统提示组装抛掉，会话直接坏。

`interpolate: false` 在类型里是明确支持的（`dsh-system-prompt/lib/types/index.d.ts:61-62`：*"Defaults to true; false preserves literal text."*）。

> 另外**仍然做一次字符串级兜底**：把注入文本里的 `{{` 替换成 `{ {`（中间插一个空格）。双重保险，因为 `interpolate` 是可选字段，将来若有人手滑删了，兜底还在。这一条对应任务书说的「`{{` 必须转义」，我把它做实到这里。

### 3.9 注入位置：`order` 该排在哪

旧插件 `order: 900`（`index.js:1037`），注释说「排在运行时上下文之后」（`index.js:1036`）。对着框架的常量表核一遍：

`CONTEXT_ORDERS`（`dsh-system-prompt/lib/index.js:44-52`）：

```
WORKING_DIRECTORY 100 · SANDBOX_POLICY 110 · APPROVAL_POLICY 115
SUBAGENT_DELEGATION 120 · TEAM_IDENTITY 125 · HARNESS_SOURCE 200 · WEB_SURFACE 210
```

`SECTION_ORDERS`（`dsh-system-prompt/lib/index.js:10-43`）里 `HARNESS_SOURCE: 1e4`、`WEB_SURFACE: 10100`、`DEPLOYMENT_PERSONA_SUFFIX: 10200`。

> 两处修正：

> 1. **900 太大。** 它排在 `WEB_SURFACE(210)` 之后很远，但 `systemPrompt.context()` 的 entry 最终落在 `contexts` 数组里（`dsh-system-prompt/lib/index.js:394` 按 `order` 排序），**persona 走的是 section 不是 context**（`dsh-persona/lib/index.js:36-46`，`getSectionOrder("DEPLOYMENT_PERSONA_PREFIX")` = 0）。所以「记忆段」和「人设段」根本不在同一个序列表里，900 这个数和人设无关。

> 2. **新壳子建议 `order: 300`。** 理由：要排在 `HARNESS_SOURCE(200)` / `WEB_SURFACE(210)` 之后（事实在前，心事在后），又不要太靠后 —— 900 会让她那几句自己的判断落在整段运行时上下文的尾巴上，离她真正要接着说的话太远。

### 3.10 注入块拼装代码的落点（写清「改哪里」，不是伪代码）

内部三件事（与 `index.js:1038-1112` 一一对应，换掉内容、保留结构）：

## 4. 判断性遗忘和「会改自己」在提示词层怎么表达（汇总）

任务书第 3 问。上面 §3.3(c)(d) 已经给了形态，这里只把**边界**说清楚，免得被做成假绿：

| 能力 | 提示词层的落点 | **明确不做** |

|---|---|---|

| 会改自己（`retired` + `was`） | 三行同时在场（旧 / 为什么改 / 现在），且同一主题只摆最近一条 | **不写「我错了」**。她不是被纠正过、不是认错，是「后来不这么想了」。差别在动词：`改` vs `认错` |

| 会忘（沉下去） | 最多一个空位，且不写被沉下去的内容 | **不写「我忘了什么」**、**不写「我的记忆里本来有…」**、**不列遗忘清单** |

| 会追问（`open` + `tension`） | 一行「还没想明白」+ 一行「这回该看什么」+ 一行次数 | **不写成问句让主人回答**（`spec/规格主轴.md:308` F4-f：追问不是插话，不许主动向主人提问） |

| 会想多（同主题演变） | 由 §3.7 第 1 条兜住：同主题只出现一条，且是**最新**的那条 | **不摆历史轨迹**（`turns` 有完整记录，`src/judge.mjs:160-171`，但摆出来就是清单） |

**「会想多」这一条要单独说一句**：它的价值全在**「现在的这一句，和上次那一句不一样，而且这个不一样是算出来的」**（`src/judge.mjs:223-232` 的 `changeOf`：谓词变了 / 立场变了 / 底气变了 0.12 以上，才算变）。

落到提示词层，**唯一要保证的是：她这一轮看到的是最新的那句。** 不要塞「上次我是这么说的」——那会让她开始表演「我在成长」，比记不住更假。

## 5. 迁移路径：并存 / 替换 / 迁移，三条的取舍

### 5.1 三条路径各是什么

| 路径 | 做法 | 现有 `brain-mem` 怎么办 | 存量 380 条怎么办 |

|---|---|---|---|

| **A 并存** | 新插件用另一个 id（如 `mind`）与 `brain-mem` 同时挂在一份 patch 里 | 原样跑 | 原样留着，两份记忆各说各的 |

| **B 替换** | 停用 `brain-mem`，新插件沿用同一个 id | 摘出 patch，文件留着备份 | 不导，从空库开始 |

| **C 迁移** | 用一个一次性导入器，把旧库里有价值的东西烧成判断，再替换 | 摘出 patch + 归档旧目录 | 挑过的部分进新库 |

### 5.1.1 一条已经发生的事实：主人已经选了「替换」

2026-10-26 17:51，主人亲手把 `~/.dsh/profiles/web/plugins/brain-mem` 卸掉了：`plugins/` 下只剩 `session-rescue`，`cordis.patch.yml` 里已经搜不到 `@local/dsh-brain-mem`，并且留下了两份完整备份（源码快照 `plugin-src-full\`、记忆数据 `brain-mem-dotdir\`）。

**这不是意外，是主人主动的选择。** 它把下面 5.2 里「A 并存」那一条从「我不推荐」直接变成了「已经不可能」：**主人自己腾了位置，他就是要换掉旧的那个。** 本文后面所有关于「先替换、再导入」的说法，都是在这个既成事实之上把路走完，不是另起一个方案。

### 5.2 逐项取舍

**A 并存 —— 不推荐，而且是三重不可接受：**

1. **两段注入会打架。** 两个插件都往 `systemPrompt.context()` 里注册，两段都在（各自的 `name` 不同就不算重复注册）。旧块带着「想起：<祈使句>」进来，新块带着判断进来 —— 结果是她一边被告知「直接当成你记得的事」，一边被告知「我是这么以为的」。**气质直接对冲。**
2. **两个过滤器 = 两个漏。** `isSystemInjected()` / `isHarnessReminder()` 那段（`index.js:236-290`）是拿血换来的，两个插件各写一份，早晚有一边漏一条。旧插件那天在库里抓到 10 条噪音、「一条都没被旧规则拦下」（`index.js:257-261`）—— 那是**一个**插件补了四类之后的结果。
3. **内存里两份召回缓存。** `lastRecall` / `memIndex` / `featIndex`（`index.js:653-732`）各自独立，各自在每条 user 消息上跑一遍（`index.js:1337`），两条召回各自抢 `lastRecall` —— 到底哪一段进提示，取决于谁的异步先回来。**这是不可调试的竞态。**

**B 替换 —— 可行，但会白白丢掉旧库的全部数据。**

丢掉的原因不是「旧库没用」，是「旧库进不了新库」。§3.1 已经说了：旧库 380 条里，`state` 有 245 active / 135 archived，但 `trend` 380/380 全 stable、`uncertain` 0 条、`resolved` 0 条、`assess_rounds>0` 0 条、`prune_rounds>0` 0 条（本机 `store.json` 实测，与 `spec/规格主轴.md:24-30` 完全一致）。

**这一组数字合起来的意思是：旧库没有任何一条经历过「演变」「拿不准」「想通了」「自我复核」「判断性遗忘」。** 它就是一批原话加一批说法不同的同义句。

从零开始不是浪费，是**不带着病开始**。

**C 迁移 —— 推荐，但「迁移」的定义要收窄。**

不是「把旧库倒进新库」，而是：**用旧库里极少数的真判断，去说服新内核开张。**

具体做法（一次性脚本，跑完即弃，不入常规链路）：

1. 用 `spec/规格主轴.md:99-106` 那张表当筛子，**只挑「有谓词、有极性、材料里没有这句」的**。那张表已经点名了几条合格的（`mem-000258`「他是把这件事交给我，不是交给我一个任务。」、`mem-000312`「他们只问放上去没有，没问改得对不对。」）。
2. 这些挑出来的条目，**不直接写进新库**，而是当成「经历」喂进 `mind.ingest()`，让 forge 自己决定要不要烧、烧成什么。这样它们和新判断走同一条路，格式、谓词、极性、理由全部由内核把关（`src/forge.mjs:225-244`）。
3. 有一条**必须走另一条路**：`kind=identity` 的 23 条（本机实测；`index.js:2228-2260` 的 `persona_seed` 把它们按 `identity`，即强制 critical，写进去）。身份不是判断，是「她是谁」，新壳子应该**从 `persona` 配置重新 seed**（`index.js:2237-2259` 那段的逻辑照搬），不走导入器。
4. 导入完成后**归档旧目录**（改名 `.brain-mem-archived-<日期>`），**不删**。哪天要查「那句话是从哪来的」，旧库还是唯一证据。

> 为什么不推荐直接导全部：`spec/规格主轴.md:104-106` 已经判过那 30 条同主题的：它们「本身不是原文，但**只能以『同一判断的演变』存在，不许 30 条并存**」。全量导入 = 把这条禁令原样搬进新库。

### 5.3 推荐方案与执行顺序

> **推荐 C：迁移，但先 B 再 C —— 也就是说，先替换上线（空库跑通），再单独跑一次导入器。**

理由有三条，全是可执行的：

1. **替换是必须的，不是可选的。** 上面 A 的三条不可接受里，第 2 条（两个过滤器 = 两个漏）**只要两个插件同时在跑就会成立**，跟库里有没有数据无关。而且这一步主人已经亲手做了（§5.1.1），新插件要做的只是把位置接过来。
2. **空库先跑通，才能分清「新壳子坏了」还是「导入的数据坏了」。** 这是旧插件吃亏最多的地方：`index.js:611-616` 那两行 `process.stderr.write('brain-mem: apply() entered')` 的注释 ——「之前两种都静默，白查了好几轮」，`index.js:617-631` 的 `plugin-alive.json` ——「光看文件时间戳永远分不清『已生效』还是『还没重启』」。**新壳子从第一天就要有这两样，且第一天必须只有一变量在动。**
3. **导入器是可选的一次性动作**，失败了不影响新壳子照常跑（空库就是最干净的起点）。这是唯一一种「失败了也不回滚」的迁移。

**执行顺序（七步，每步带验收）：**

## 6. 验收：这份设计自己能被打成红的那些点

文档不写「应该没问题」。下面是**能直接判真假的断言**，全部对着 §3 的形态：

1. **J1 零引导语**：注入块里出现 `/记忆|想起|提示|指令|请你|不要忘记|以下是/` 任一 → **红**。
2. **零祈使**：块内任一行以 `去 | 把 | 别 | 要 ` 开头，或含 `你现在` → **红**（旧块 `index.js:1064` 就是这种）。
3. **每行可独立成句**：把块里每个 `- ` 行删前缀后，长度 ≥ 8 且不以「：」开头 → 通过；否则红。
4. **同主题只一条**：块内所有 `themeKey` 无重复 → 通过。
5. **`retired` 三行齐全**：每条 `retired` 必须有「以前 / 后来 / 现在」三行，且「后来」那行字 ≥ 6（`spec/规格主轴.md:352` 的 F5-e 同款） → 否则红。
6. **`open` 必须带 `probe`**：任一 `open` 行进块但没有「这回该看什么」→ **红**（§3.3a）。
7. **`{{` 不炸**：注入文本人为塞一个 `{{foo}}`，`assemble()` 必须正常返回 → 炸了就是 `interpolate: false` 没生效（§3.8）。
8. **键一致**：一次真对话里，事件侧 `keyOf(session)` 与 `text()` 侧 `keyOf(scope)` 必须逐轮相等 → 不等就是键错误（§2.2）。
9. **不串会话**：两个会话并发跑，各自 `lastRecall` 互不可见 → 串了就是 `lastFallback` 又回来了（§2.3）。
10. **两段式仍在**：把 `src/flash.mjs` 的 `recall()` 人为改成 async 并加 200ms 延迟，**注入块必须照常出现**（只少了最新那条），不许变空 → 变空说明同步层被做成了异步（§1.3、`index.js:712-720`）。

### 7.1 关于第 3、4 条：为什么新壳子要「一个硬依赖都不写」

旧插件那段注释（`index.js:208-214`）写得比我说得好，照抄：

> Cordis 的 `_refresh()` 只要有一个 inject 服务拿不到，就把整个 fiber 置成 INACTIVE —— `apply()` 永远不执行、也不报错。实测（大乔 2026-10-25 A/B 对照）：inject 有 `systemPrompt` 时 `apply` 从不被调用；去掉后立刻活。表现就是「既没有 ready、也没有 disabled by config」。

新壳子对 `systemPrompt` / `llm` / `agentDefaultModel` / `agents` / `webServer` 五个服务的依赖强度**和旧插件完全一样**（都不是非有不可），所以 `export const inject = []` 原样保留（`index.js:216`）。

尤其 `llm`：新内核的整条链路靠 `synthesize()`（`src/forge.mjs:85-88` 构造时强制要求注入），拿不到 llm 就**整条链路停摆**。旧插件给这件事定的调子是对的（`index.js:1126-1135` 注释：「llm 服务不在，就永远退化成纯 n-gram」）—— 新壳子没有 n-gram 退路，所以更要**先起来、再降级**，绝不能因为 llm 不在就整个插件不起来。

> 具体降级：`synth` 拿不到 → `mind` 构造不出来 → 注入层永远返回空段 → **她表现得像没有记忆，但对话完全正常**。这一条要写进 README 的排错表。

### 7.2 patch 文件的三条写法（原样抄自 `cordis.patch.yml` 头注释）

1. 插件的 `cordis.patch.yml`、`index.js`、`package.json` **必须一起放进插件目录**：`package.json` 的 `dsh.bundle.patch` 指向它，缺了它 bundle 配置就是空的，插件永远不会 `apply()`（`package.json` 里 `"patch": "./cordis.patch.yml"`）。
2. **新条目用 `- insert:`**；顶层 `- id:` 是「覆盖已有条目」，新 id 会报 `entry not found`。
3. **`storePath` / `aliveDir` 不写**（留空串会把推导值覆盖掉）。

## 10. 三句话总结

1. **钩子**：`user/message` 采集、`systemPrompt.context()` 注入、`step/end` 收尾三个都保留骨架；`tick`（定时衰减）取消，因为判断性遗忘是「记下新的才腾地方」（`src/fade.mjs:43-44`），不是定时器。
2. **注入形态最关键的改变**：从「一段被喂进去的结论 + 解释她该怎么用它的引导语」，变成「**她自己想出来的一句话 + 为什么这么想 + 她以前不这么想**」，且**一句引导语都不许有**。判据：块里每一行删掉前缀都能接在「我想：」后面念出来。
3. **路径**：**先替换（空库跑通一周），再单独跑一次性导入器**。并存不可接受——两个过滤器就是两个漏，两段注入气质对冲，两套召回缓存是不可调试的竞态。而且这一步主人已经用卸载表了态：他要换掉旧的那个。
