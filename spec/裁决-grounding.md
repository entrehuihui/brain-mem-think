# 裁决三：grounding 的口径

**日期**：2026-10-26
**裁决人**：大乔（Lead）
**触发**：`f_unknown_wording` 实测 2/5，红队的诊断是「瓶颈已不在主题归一，在 grounding」

---

## 一、现场

```
F1a  骨架重合收敛   0 种
F1b  模型自认收敛   0 种（这条路还没铺）
F3a  两条路都丢     3 种：unknown_b / unknown_c / unknown_d
F1   主判据        2/5（门槛 3）
```

三种丢法，死因**不是同一个**：

| 说法 | 死因 | 本质 |
|---|---|---|
| `unknown_b`（夜里三点还在回消息） | `predicate_unstable` | 模型换了个谓词 → 主题槽认不出 → **自认通路能救** |
| `unknown_c`（杯子放凉三次没喝） | `not_grounded` | 判断正文落不回材料 → **grounding 太严** |
| `unknown_d`（打哈欠到眼睛出水） | `not_grounded` | 同上 |

---

## 二、红队说对了一件事

> 「我不会为了让 f 的好看去放松 grounding——那正是'不存原文'的命门。」

**认。grounding 不许为了让数字好看而放松。**

但「不许放松」不等于「不许修」。现在的 grounding 有个具体的错：**它按字面判断正文有没有落回材料**，这跟主题归一原来的毛病一模一样——**还是按字面，不是按理解**。

---

## 三、裁决

### grounding 的判据要从「字面落回」改成「骨架落回」

**现在的（猜的）**：判断正文里的字，要能在材料里找到。

**为什么这是错的**：`unknown_c`「杯子放凉三次没喝」→ 她熔出「他总把一件事拖到没意义了才说」。这句话里没有一个字出自材料，但它**完全落在那件事上**。按字面判，它必死；按理解判，它成立。

**改成什么**：

```
一条判断算 grounded，当且仅当满足其一：
  ① 判断的 relation|subject 与材料骨架的 relation|subject 一致
  ② 判断引用了材料里的具体对象（subject），且 relation 出自 PREDICATES 闭集
  ③ 模型在 synth 返回里显式声明 groundedIn: [材料序号]，且内核复核该序号存在
```

**三条路里第一条是主路，第三条是兜底。**

### 硬约束（防止变成万能后门）

1. **`groundedIn` 不许凭空指**。指的序号必须在 forge 窗口里真实存在，否则整条废。
2. **不许把原句抄进判断**。`copied_from_source` 那条 8 字闸**一动不动**。
3. **`groundedIn` 不能替代 `theme` / `themeOf`**。一条判断可以 grounded 但不属于某个主题（那它就是新的），也可以属于某主题但 grounding 失败（那它就丢）。

---

## 四、这条裁决的代价（明说）

**grounding 放松之后，模型胡编的风险变大。**

原来的字面闸很笨，但它有个好处：胡编的句子一个字都对不上，必死。
改成按骨架判之后，一句「他就是这样的人」可能因为 `subject` 对上就算 grounded——**但它可能根本没发生过**。

**这是这套设计的固有风险，不是疏忽。** 主人要的是「想」，想就会想错。存储体不会想错，它只会记错。

防这条靠的不是 grounding，是**「会改自己」**：想错了，后来的事会推翻它。**所以 d 那条链必须修通——它是 grounding 放松的唯一保险。**
