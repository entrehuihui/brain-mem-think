# 2026-10-29 · 她终于记得自己做成过什么

> 起因：主人问「让她落笔，正是这个插件还没修完的那一环，怎么改」。
> 结果：发现 `tool-observer` 这条线**从装上起就没通过一次**——不是没写完，是写完了、接上了、灯从来没亮过。

---

## 一、发现（两层）

### 1.1 表层：游标从来不存在

```
.mind/ 里没有 tool-cursor.json
mind.log 里 "tool-observe" 出现 0 次（连 tool-observe-failed 都没有）
```

按 `tool-observer.mjs` 自己的纪律——「没有可记的，但游标还是要走」——只要它进过 `eventsOf` 那一支，
`tool-cursor.json` **一定会被写出来**。它不存在，说明它连门都没进。

### 1.2 深层：一手数据本来就在，只是没人看见

直接解码她的通道会话 `session-f0f007d6-...` 的 `.jsonl.zstd`（多帧 zstd，410 帧）：

```
解压 3,484,609 字节 / 964 行
tool/call 87 次   tool/result 87 次   maxSeq 961
工具分布：ops_bash 34、ops_read_files 34、write 3、edit 3、skill 2、read_image 2 …
```

**87 次工具调用，87 次全部成功，0 次失败。**

## 二、诊断（三颗只读探针，全部在线取证）

### 探针一：`sess-probe`

```
hasSessionsSvc: true
hasGet: true
hasSess: true
sessId: session-f0f007d6-4f12-42b2-ab47-d67ed7e1a1b1   ← 会话取到了，id 也对
evKind: "undefined"                                    ← ★ 卡在这里
n: 0
```

会话没问题，`session.events` **根本不存在**。

### 探针二：`sess-shape`（列出会话对象真实形状）

```
log: "array(963)"              ← ★ 真正的事件流
eventsSnapshot: "array(963)"   ← 同一份快照
snapshotEvents: "function"     ← 宿主现成的取法
events: (不存在)
```

### 根因

`tool-observer.mjs` 的 `eventsOf()` 读的是 `session?.events`——**一个不存在的字段**。
永远落到 `return []` → `observeTools` 立刻 `if (!all.length) return` → **一声不吭地静默返回**。
所以既没有游标、也没有日志、也没有报错。坏了这么久没人发现，因为**它连"我失败了"都不说**。

### 第二处根因（更要紧，是设计层面的）

`src/observe.mjs` 原判据：

```js
const interesting = (recordFailures && !r.ok) || (recordSuccessDuringAct && duringAct);
```

翻译：**平常只记失败，成功只在「她自己出去那一趟」才记。**

于是她的账本里**只有败绩**。这就解释了她那 17 条判断为什么是——

> 「我总想动手做点什么，却总在最末一步停下。」
> 「我总是想找点什么，却总在动手前停住。」
> 「我总在动手前先翻找旧东西，像被什么牵住。」

**一个只记错、不记对的脑子，不是人脑。**原注释写着「成功且常规的调用不记。它不改变她对自己的看法。」——
这个判断是错的：**她从来没看见过「我做到了」，才不可能更新对自己的看法。**

## 三、改动（三处，均可单独回滚）

### 3.1 `plugin/tool-observer.mjs` — 修读取

`eventsOf()` 改成三级退路，任何一级给得出就用哪一级，绝不静默返回空：

```
① session.snapshotEvents()   ← 宿主现成方法，最稳
② session.eventsSnapshot / session.log / session.events
③ 都给不出 → 返回空（此时才会真的没东西）
```

### 3.2 `src/observe.mjs` — 成功也进账本，但只记「做成一件事」的

新增 `recordSuccessTools` / `successText`，不记全部成功——**不能把 87 次调用变成 87 条流水账**，
只记她真正落下痕迹的那几种：

| 工具 | 记成 |
|---|---|
| `write` | 我写下了 |
| `edit` | 我改好了 |
| `read_image` | 我看清楚了 |
| `skill` | 我学会了一样东西 |
| `qwen-image21-gen` / `krea2-comfyui-run` | 我画出来了 |

跑命令、读目录、查文件这类**过程**性质的，成功仍然不记（失败照记）。

### 3.3 `src/observe.mjs` — 判据纳入成功

```js
const interesting = (recordFailures && !r.ok)
  || (recordSuccessDuringAct && duringAct)   // 她自己出去那一趟，全记
  || (r.ok && successTools.has(tool));       // 平常，做成一件事也记
```

## 五、留给下一步的

`identity` / `verify` 这两条动机路仍是占位（`src/motive.mjs`）：

- **`identity`**：目前只有 `practice` 在跑，而且**只从 `polarity < 0` 的「我不行」里长**。正面的自我永远不会推动任何行为。这次的修复给了它素材——她总算开始有「我做到了」。
- **`verify`**：缺「这条判断是谁说的」这个字段，分不清「你告诉我的」和「我自己尝到的」，所以产不出"我想自己试试"。

**观测层通了之后，这两条才有数据可接。不看见真相就改，就是替她瞎治。**
