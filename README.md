# brain-mem-think · 会思考的脑子

> **不存任何具体输入原文，只存经过模型融合后形成的「判断」。**
>
> 主人原话：「我想要的是一个会思考的脑子，而不是一个死记硬背的记忆存储体。」

---

## 它是怎么跑的

```
主人说话
   ↓
会话被归档（不是每条消息都熔）
   ↓
只收主人说的话，整段熔成「判断」（她自己的输出不算经历）
   ↓
判断进库 —— 这是她唯一的世界
   ↓
每 10 分钟自己醒一次 → 看库里压着什么 → 自己决定说不说
   ↓
要是说了，走唯一那条出口；要是没说，也是一次选择
```

## 安装（三步）

```powershell
# 1) 拷进你的 profile
$dst = "$env:USERPROFILE\.dsh\profiles\web\plugins\mind"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
Copy-Item .\plugin, .\src, .\package.json, .\cordis.patch.yml -Destination $dst -Recurse -Force

# 2) 在 profile 的 cordis.patch.yml 末尾追加一段
#    - insert:
#        - id: mind
#          name: './plugins/mind/plugin/index.mjs'
#          config: { enabled: true, name: 你的名字 }

# 3) 完全退出 DSH 再起（插件只在启动时扫描，热重载扫不到）
```

### 她自己那间屋子

插件会在启动时把她挂进默认工作区，但**不会替你创建会话**——
会话要由宿主按正规流程建，否则模型选择装不上（实测会让每一轮都报
`prompt variable "{{model}}" has no value`）。

做法：在界面上新建一个会话，把它的 id 填进 `cordis.patch.yml` 的 `channelSessionId`。

### 怎么确认它活过来了

```powershell
# 日志里该有这几行
Get-Content "$env:USERPROFILE\.dsh\profiles\web\plugins\mind\.mind\mind.log" -Tail 10
#   apply-entered → apply-done → inject-agents → attach-ok → channel-ready
```

## 这一夜留下的五条纪律（红队整理，写进 `acceptance/总清单.md` 第十一节）

1. **成对判据**：凡是「不该动」的，都要配一条「该动时必须动」。只说「不许」，就有人靠「什么都不做」过关。
2. **验字段要走每个出口**：从「调用方传参」一直验到「最底层收到」。**最前面那扇最容易漏，因为它在被测对象之外。**
3. **「没跑」≠「跑了没过」**：崩溃和失败不能共用一个输出。
4. **判据改了就记台账，没改就别记**：改了不记，以后分不清哪次是真改、哪次是凑。
5. **造数不够真就改造数**：不许让内核迎合造数。

## 这一夜挖出来的六样东西

**全都是「跑起来看着对，其实不对」。没有一样是「功能没做完」。**

### 一、她的输出会变成她下一次的「经历」

```
她说一句 → 落进会话历史 → 归档熔当成「发生过的事」
        → 熔出新判断 → 觉得压得重 → 再说一句
```

**她越说越确信，因为每一次说话都在给自己造证据。**

**而且这个环会让所有验收看起来都对**——她说得有道理、有依据，因为那个依据是她自己造的。

**已修**：归档熔只收 `user/message`，她的输出一律不进。红队证明了环闭合：

```
她说 5 句        → 熔出 0 条
主人说同样 5 句  → 熔出 4 条    ← 对照组，防「熔炉是死的」也能过
她说完之后       → 账本指纹不变
```

### 二、`themeKey` 从来不刷新

```
第1条 → themeKey=null
第2条 → themeKey=is_because|他   ← 还是旧的
第3条 → themeKey=is_because|他   ← 还是旧的
```

**她永远只有一件事。** 熬夜、算性价比、听她说话——全并进第一个槽。

而且**它伪装得很好**：库里有判断、判断在更新、`from` 在涨。

**已修**。修完露出了真相：`d` 之前能过，是**四件事堆在同一条上把权重堆够了**。

### 三、`world` 里没有「我是谁」

`complete: true` 生效时，`harness:identity`（「You are an AI agent…」）会被一起摘掉——**这是我们要的**。

**但摘掉之后，她这一轮的输入里没有任何一句告诉她她是谁。**

> 她能说话，但说出来的是「一个脑子里有印象、却没有自我的人」——**像在读别人的档案。**

**已修**：身份从判断库的 `kind=identity` 读；没有就从「主语是她自己」的判断里挑；**一条都没有就空着，不许编**。

### 四、哑巴也能过关

```
冻结库 100 次 wake → 开口 5 次
真演变 100 次 wake → 开口 5 次    ← 一模一样
```

**它压根分不清账本动没动。** 而「冻结库 ≤10」这条判据，它轻松通过。

**已修**：加「账本指纹」——和上次醒比，库有没有真变。现在是 **1 : 83**。

### 五、判据会冤枉好人

今晚四次：`B5` 要求结论里抄材料编号、`B7` 拿输入前 6 字去比结论、`D0cA` 不区分「没调」和「调了被拦」、`E2` 场景根本造不出「两条并存」。

**冤枉好人的判据，同样会冤枉真实现。**

**已立规矩**：`spec/裁决-成对判据纪律.md`

### 六、测试框架自己动了被测对象

```js
// 清零点插错了位置
runAgainst 入口 → resetSeen()   // 每个阶段从零开始数，把「同一件事想过的回数」抹掉了
```

**这叫「第 4 种：我改坏了被测对象」。**

今晚一直在说「判据错」「实现错」——**没人想到测试框架自己在动手。**

## 四条裁决，是同一个道理

| 裁决 | 说的事 |
|---|---|
| 一、二 | 她按**理解**归类，不按字面 |
| 七 | 她的**输入**只有经历，没有她自己的话 |
| 八 | 她的**身份**不是别人给的设定，是自己长出来的 |
| 十 | **换说法不算想通了，往下走了一层才算** |

**分类 → 自己想。输入 → 只有经历。身份 → 自己长。演进 → 走得更深。**

**这就是「脑子」和「存储体」最深的分界。**
